## 1. What landed

Under incompat bit 17 every metadata writer is an **appender** (design §5.3): a 4 KiB **page** that is at once its directory entry and its ledger record, a journal ring that is a **segment table** of heap extents, and (from PR 3) an extent grant. This PR lands the durable unit, the directory, the segmented ring, the mounted region — identity binding, own-residue recovery, the foreign refusal, the page per checkpoint, ring growth, the flush-ceiling audit, the release at unmount — the declared-partition seam that stands two regions up in one process, the per-ring violation classes, the verb, the gauges, the fuzz target. Everything is **dark**: nothing stamps bit 17 but the PR-1 seam, and a bit-17-absent volume is byte-identical (§2).

### 1.1 The on-disk shape (`src/meta_backend/kv/appender.rs`)

- **The page** — LE, 4 KiB, xxh3_64 with the field zeroed: `magic ‖ appender_id ‖ generation ‖ xxh3 ‖ node_token ‖ writer_id (u128) ‖ mount_slot (u32) ‖ state ‖ is_manager ‖ home_volume ‖ term ‖ recovered_by_term ‖ ring {n_segments ≤ 8, segments [ExtentRef; 8], head_hint} ‖ ledger_tail_seq ‖ ckpt_seq ‖ grant {n_runs ≤ 4, runs [(start u64, len u32); 4]} ‖ slots {n ≤ SLOT_PAGE_BUDGET, entries}` — fixed part **306 B**, entry **35 B** (`slot u16 ‖ state u8 ‖ g u32 ‖ slot_tree_extents u32 ‖ root (u64, u64) ‖ cursor u64`), **`SLOT_PAGE_BUDGET = (4096 − 306) / 35 = 108`** (computed; tie-tested). Decode is TOTAL and canonical (every count is a claim checked against its bound before an element is read; unused table entries, grant-run padding, reserved bytes and the tail must be zero; slot entries slot-ascending) — `classify_page` answers `Blank` / `Valid` / `Corrupt`.
- **Four page slots per appender**, written round-robin by generation (`page_slot_for`), read **newest-valid-wins** (`newest_valid`): the directory pair `[A, B]` and the ring-side `[R0, R1]` — the first two pages of the ring's first segment. A torn newest falls back twice (pinned).
- **Appender 0** = the format-time fixed ring: its four page slots are the fixed journal extent's first four pages (`APPENDER0_RESERVED_PAGES`), its ring the rest (`appender0_ring_extent`). **Appenders ≥ 1** live in the **directory**: a chain of heap extents `superblock.appender_dir` names (sector-0 offset 136, inside the zero padding), each one `node_size` extent holding `(node_size / 4096 − 1) / 2` page pairs (7 at 64 KiB nodes, 31 at 256 KiB, 127 at 1 MiB) and a checksummed `DirHeader` LAST (magic, chain index, `next`, pairs). Format under the seam claims the first extent, writes its header and appender 0's `Free` page.
- **The ring is a segment table** (`journal::RingSegment`, `JournalRing::segments` / `page_offset` / `new_segments` / `recover_segments`): the shipped ring is the one-segment case — every constructor, page header and replay byte unchanged (`kv_journal_tests` + `kv_partitioned_append_tests` pin it). **Growth** (`grown_with`) answers a NEW ring over `segments ‖ extra` continuing at the logical head — legal only on a DRAINED ring (head == reusable_upto, no reservation open): the page map changes for every position on lap ≥ 1, so an in-window record would be read from the wrong page (the module's re-partitioning law); refused past the eighth segment.
- **Derivations**: `SYM_RING_FLOOR_BYTES` = the §4.4 pt 5 checkpoint reserve (256 KiB) + one `MAX_ENTRY_LEN` (128 KiB) rounded up to a power of two = **512 KiB** (a whole number of shipped extents); ceiling = `journal_ring_len(volume)` (the solo ring's own derivation); default `clamp(2 × ewma_commit_bytes/s × CHECKPOINT_MAX_AGE, floor, ceiling)` — a fresh join has no EWMA and takes the floor; `appenders_capacity = heap/16 ÷ ring`; the flush ceiling `appender_flush_ceiling_ms() = CHECKPOINT_MAX_AGE_MS` (KD-SYM-10, stated once). `SQUEEZEFS_SYM_RING_KB` explicit-wins (clamped to the volume's ceiling, logged).

### 1.2 The mounted region (`KvMetaBackend::appenders`, `AppenderSet` / `AppenderRegion`)

- **Open**: the forest arm reads the directory; a writer binds `(node_token, mount_slot)` (the engaged writer scope, else the node token + `mount_slot()`; a box with no node-identity material falls back to a boot-scoped token). A `Live` page of our own = our predecessor died un-recovered — the ledger replay just performed IS region 0's recovery (`appender_self_recoveries`); a **foreign `Live` page refuses the writer open loud** naming PR 10 (the dead-appender recovery driver) and `squeezefs appender clear` (a probe / `-o ro` reader lists it and mounts what tree 0 names). Every region the declared partition names gets its page from the directory (refused if the first extent's pairs are exhausted — the chain grows only under PR 3's `JoinAppender`) and a ring: replayed from ITS page's segments and tail when the page is our own `Live` (own-residue), else fresh from the heap (whole extents, internal class, adjacent ones coalesced into segments; a `Recovered` page re-adopts with a fresh ring, never replayed — §5.8.3). The three violation classes run over EVERY ring's window before any recovered content is applied. A page's NEWER roots are adopted (node seqs mint monotonically) and a slot tree 0 does not name is opened from the page — a declared region's page is its content's only durable home once the tail passes the flushed leaf.
- **Join / leave**: `join_appender_regions` runs after the D0 claim gate (`Live`, term + 1, the writer id stamped, one barriered checkpoint — which also lands the bitmap bits of any ring extents claimed at open BEFORE a page names them); `leave_appender_regions` at a clean unmount writes every page `Free` (id and term kept; a declared region's extents released; the Free page goes to the DIRECTORY pair only — its ring-side pages sit in extents just returned).
- **The conveyor routes by region**: `build_queued_tx` resolves a tx's region from its records' slots (`region_of_records`; a tx spanning two appenders is PR 6's cross-owner operation and refuses); `run_batch` runs the pipeline once per region group, reserving in THAT region's ring (`PassSentinel.ring` / `ConveyorWindow.ring`; the lane completes, prefix-waits and hole-checkpoints per ring — `checkpoint_past_region`); the unpartitioned volume is the one-group case. Region-attributed `journal_full_stalls` per region.
- **The checkpoint cycle**: (a) `grow_stalled_regions` — a declared region whose ring stalled since its last growth decision and is drained gets one segment (up to the ring's current size in contiguous extents): bitmap pages + barrier, the page naming the grown table + barrier, THEN the swap, under the Dekker pair `passes_inside` / `growing` with `run_batch_group` (a pass never reserves on a ring being replaced); (b) one TAIL PER REGION (`appender_region_tails`: its head, its open reservations, the floors of ITS slots' leaves — `NodeCache` keeps slot-stamped LEAF dying floors per slot, `take_dying_leaf_floors`, because a leaf's floor is a position in its lessee's ring; interior nodes, tree 0 and every flat node fold into the manager's tail as before); (c) `write_appender_pages` after the ledger — region 0's mirrors it (tail, `ckpt_seq`) and names the roots it holds (≤ the budget; never tree 0's or the stamp — KD-SYM-3), a declared region's names ITS tail and roots; each tail rides the region's pending-reclaim ledger with the barrier epoch, `after_durable_barrier` advances each ring's `reusable_upto`, and the cache's elision tail becomes the MIN over regions; (d) `note_flush_ceiling` — a pass that began with a region's dirty leaves and reached its covering barrier past the ceiling is one `appender_flush_ceiling_overruns` per such region.
- **Violations** (`journal::detect_appender_violations`, the bit-8 detector's per-ring successor; must-stay-0 gauges `meta_kv_replay_{key,lease,extent}_violations`): `Key` — one `(kind, key)` in two rings' windows; `Lease` — a content record outside the ring's appender's lease set (the manager leases the complement) or the manager's STRUCTURE in a content ring; `Extent` — an allocator delta in a ring whose appender holds no grant (until PR 3, every extent is the manager's). Window-scoped like its predecessor.
- **Verb**: `squeezefs appenders` (a probe; refuses a bit-17-absent volume naming the seam and PR 11). **Gauges**: `appender_id`, `appenders_live`, `appenders_capacity`, `appender_joins`, `appender_leaves`, `appender_self_recoveries`, `appender_ring_bytes`, `appender_ring_segments`, `appender_ring_grows`, `appender_flush_ceiling_overruns`, the three replay tripwires — per volume, 0 on every bit-17-absent mount.

## 6. Found on the way (and deviations from the PR row — for adjudication)

1. **`SLOT_PAGE_BUDGET` is 108, not 122.** The design's 31 B entry predates Rev 3's `slot_tree_extents: u32`; at the §5.3.2 field list's natural widths an entry is 35 B and the page's fixed part 306 B, so `(4096 − 306) / 35 = 108`. The budget is COMPUTED from the codec's own constants and tie-tested; `mount_slot` is carried at its shipped u32 (the KD-MW-2 derivation truncates `xxh3_64` to 32 bits — a u16 would lose bits). The design's row is annotated; §5.1.3's LRU release (PR 4) applies at 108.
2. **The directory header costs one pair per extent.** "32 page-pairs + a `next` pointer" in one 256 KiB extent do not fit (64 pages); the header page is LAST and an extent holds `(node_size/4096 − 1)/2` pairs — 31 at the default node size. The chain is one heap extent per link (the allocator claims one extent at a time), so the "256 KiB" of §5.3.1 is the default node size, not a constant.
3. **Structure stays the manager's in PR 2 (§5.2.3 owed to PR 3).** A declared region's content — leaf records — journals into its own ring; its slot trees' interior flips and every allocator delta journal into ring 0. The reason is §5.3.3 itself: an appender's `alloc(extent)` record is its own only inside an extent GRANT, and grants are PR 3's; without one, an appender's alloc record in its own ring would be exactly the `Extent` violation. This is what makes the per-region tail sound with one dying-floor accumulator per slot and one for everything else: a leaf's floor is a position in its lessee's ring, an interior node's in the manager's. `AppenderViolation::Lease` names the manager's structure in a content ring so PR 3's move is a red test away.
4. **Region 0's ring never grows.** The fixed ring is the format's `--meta-journal-mb` decision (the solo derivation's ceiling on a default format); growth is for appenders ≥ 1, whose rings start at the floor. A growth event adds ONE contiguous segment of up to the ring's current size (the run breaks at the first non-adjacent extent; the remainder is released).
5. **The second appender is a seam, not a mount.** Two `KvMetaBackend`s on one volume would be two allocators on one bitmap (the bit-8 partition the design retires) and two node caches (the §4.9a violation); the design's second appender is a second NODE with its own grant (PR 3) and leases (PR 4). PR 2's "two appenders on one volume" is therefore one backend with two REGIONS under `SQUEEZEFS_TEST_SYM_APPENDER_SLOTS` — two rings, two pages, two tails, one allocator, one cache — which is exactly the product shape once PR 3/4 hand the region its grant and leases. The own-identity recovery covers every region of the mount (`appender_self_recoveries == 2` in the two-region crash).
6. **Found by the contracts while landing**: the page's segment table was re-derived from the ring's page ranges at every checkpoint, so a declared region's first extent lost its two ring-side pages once per cycle and recovery read the ring 8 KiB off (the two-appender replay answered `block_ref_count == 0` for refs the digest said were there, and the lease-violation contract found no records to refuse). The table is maintained at open and growth only. Also: harness premises that read the raw journal geometry (`kv_backend_tests`' raw ring writer and burial check, `crash_contract_tests` / `crash_kill_tests`' fault-arming offsets) now read the ring's own map (`physical_offset_of`, `fixed_ring_extent`); the builder's `extents_allocated` counts the directory extent; the superblock's directory gate runs after the feature gates; a writer open degraded to read-only joins nothing.
7. **A `Recovered` page** (§5.8.3) is honoured at open (fresh ring, never replayed) but nothing WRITES `Recovering` / `Recovered` in PR 2 — the recoverer is PR 10's.
8. **The reader's window is region 0's.** A `-o ro` reader replays the fixed ring from the ledger's tail and opens guest trees from tree 0 (PR 1's law); a declared region's ring window is served at the poll after that region's page and tree 0's publication — S5 bounded staleness, superseded wholesale by PR 5's tokens.
9. **The growth decision's instant** (found by the first widened-matrix run — the growth contract red on the flat leg with 6 stalls on record and one segment): growth ran at the cycle's START, where a ring reads as drained only if the PREVIOUS cycle's tail already reached its head, and a region's tail lags one cycle exactly as the ledger's (a compaction of the region's leaf retires the old leaf, whose dying floor clamps that cycle's tail) — the drained instant fell between two cycles. The decision now runs at the cycle's END, after its barrier advanced every ring's `reusable_upto`; green ×10 from zero on each leg.
10. **Per-pass cost on the shipped path**: the pass clones one `Arc<JournalRing>` into its sentinel and its window (per BATCH, not per op — beside the `Arc<ConveyorCore>` clone it already made); `region_of_records` returns before touching a record on every volume without a partition. No per-op RMW was added; `kernel_op_economy_tests` is in the verification list.
