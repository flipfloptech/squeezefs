# Hybrid I/O for O_DIRECT reads — policy landing + acceptance (2026-07-15)

**Charter**: USER DIRECTIVE (2026-07-15, verbatim intent): *"hybrid I/O between
buffered and O_DIRECT, best of both worlds, regardless of if the user is
requesting O_DIRECT or not."* Supersedes the read-path program's device-true
O_DIRECT posture (PR 4 lineage) as the DEFAULT; the ghost table is what makes
superseding it safe. Branch `feat/hybrid-io` off `3335507`.

## The policy as landed

For **reads**, O_DIRECT and buffered alike (O_DIRECT keeps bypassing the
*kernel* page cache — that side is the kernel's and unchanged; SqueezeFS's
tiers are SqueezeFS's):

1. **Serve from tier on hit — always.** O_DIRECT tier hits serve from the hot
   RAM tier / read_lru / NVMe read tier, binding-validated like every serve
   (this was already true in the shipped code and is now pinned + counted:
   `read_odirect_tier_serves`).
2. **Admission on miss — evidence-based.** Whole-block misses keep the landed
   ghost second-touch admission verbatim. The ranged (rand-4k-class) dispatch
   stops being a warmth dead-end: **first touch** = device-true window read +
   ghost record (no admit — the anti-pollution rule, unchanged); a **second
   touch within the two-epoch ghost window escalates** to ONE whole-block
   fetch through the single-flight, whose fill-site ghost check admits it
   (protected hot put + validated NVMe publish). Counted:
   `ranged_read_ghost_escalations` / `read_odirect_ghost_admits`.
3. **Churn bound (new, `EscalationCooldown`):** a key escalates at most once
   per ~32–64 s wall-clock window (GhostTable shape, two-epoch sliding).
   Fitting working sets converge once and stop; beyond-tier sets degrade to
   the device-true ranged path between windows instead of re-fetching +
   re-publishing 4 MiB per eviction (the R-5 spiral class in tier form).
4. **Budget authority unchanged:** mem-budget **Red pauses the escalation**
   (heat recording continues — mirrors the §5.7 publish-pause); everything
   admitted rides the existing gauged tiers (no new RAM class).
5. **Sequential O_DIRECT streams**: no exclusion existed — pipeline/AIMD
   eligibility is flag-blind (verified; nothing to remove).
6. **O_DIRECT writes: untouched** (durability, ack points, alignment,
   write-path publish policy; FIND-L1-A's write convoy remains a separate
   charter).
7. **Diagnostic escape** — `-o direct_device_true` (daemon-level mount
   option, stripped from kernel option strings per the M5/P1-C convention)
   / `SQUEEZEFS_DIRECT_DEVICE_TRUE=1`: O_DIRECT reads become **strictly
   device-true** — no tier serve, no admission, no ghost recording, no
   pipeline classification; passthrough volumes read exactly their aligned
   window (never single-flighted: N diagnostic readers = N device reads),
   transform volumes take a cache-free publish-free whole-block fetch
   (decode requires whole blocks). Buffered traffic on the same mount keeps
   full hybrid behavior. Mode surfaced as `"direct_device_true"` in
   `.stats`; adoption counted by `read_device_true_reads`.

## How device-true measurement works going forward (the methodology ruler)

The default mount is **hybrid**: `--direct` read rows converge to tier serves
once warm and MUST NOT be read as device-path numbers. For amplification /
device-path rows (the `.benchmarks` methodology):

1. Mount with **`-o direct_device_true`** (or daemon env
   `SQUEEZEFS_DIRECT_DEVICE_TRUE=1`).
2. Verify the posture: `.stats` → `"direct_device_true": true`, and
   `squeezefs bench --direct` prints `direct-I/O posture: device-true` in its
   header (it sniffs `.stats`; a `hybrid` line on a measurement mount means
   the flag is missing).
3. `read_device_true_reads` must equal the row's op count and `get_obj Δ /
   user ops = 1.00` — the row is proven device-true by counters, not by
   assumption (row (e): 4,194,312 / 4,194,304).

`tests/run_elbencho_mount.sh` needs no change (buffered-only elbencho line).
