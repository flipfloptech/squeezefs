**Design decisions that carry weight**

- **Lock economics:** one Mutex per registered ctx; never held across a long
  kernel wait. `io_getevents` drives bounded ~50 ms merge passes and
  re-acquires between them (split submitter/reaper pairs share the ctx at
  50 ms granularity); empty ring-pending passes park 200 µs OUTSIDE the lock
  (the adaptive-spin lesson: a spinning reaper is CPU theft from the daemon).
- **Poison law, async shape:** a poisoned session resolves in-flight tickets
  as `-EIO` events — never a silent strand, never a recycled slot (§5.7 GC).
- **`io_pgetevents` interposed:** a sigmask reaper on an intercepted ctx must
  still see ring completions; untracked ctxs keep exact real-call semantics.
- **`io_cancel`:** `-EINPROGRESS` for ring-pending iocbs; real call otherwise.

## OQ-1 economics — device-true rand-4k reads

**Instrument:** fio libaio randread 4k `--direct=1 --thread`, 15 s,
`--group_reporting`, 16×128 MiB dataset; devsub (nvme1n1 meta,
nvme5n1+6n1 data); mount `--interception -o direct_device_true`; hot tier
3 GiB; engagement = `ipc_ops_read` delta vs fio ios (all rows ENGAGED,
ring ≡ handoff ≡ op count).

| jobs=16 qd=16 | 628,378 |
| **jobs=16 qd=32 ×3** | **629,575 / 633,183 / 639,437 → median 633,183** |
| jobs=8 qd=64 | 632,162 |

**References (same box/substrate, `.benchmarks/2026-07-19-l4-interception-closing.md`):**
v1.0 il device-true `elbencho -t 256` sync median **622,112**; kernel-FUSE
device-true **604,313**; program floor **600,000**.

**Verdict.** The libaio path clears the floor and beats the v1.0
256-sync-thread shape with **16 client threads** (and matches it with 8 at
qd=64) — delivered concurrency now comes from `iodepth`, not thread count,
which is exactly the OQ-1 rationale. The ~630 k plateau across
jobs×qd ∈ {256, 512} is the daemon/substrate ceiling, not concurrency
starvation (identical plateau as v1.0's t256). The literal charter line
(`--iodepth 16`) now genuinely exercises interception and is publishable as
an il row under the standing engagement rule.

**Instrument-law update:** elbencho `--iodepth` (libaio) and fio
`--ioengine=libaio` are now VALID il instruments — the v1 prohibition
("libaio silently measures kernel FUSE") is retired for shim builds ≥ this
landing. Engagement verification stays mandatory per charter §3 rule 4.
