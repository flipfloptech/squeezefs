## Verdicts up front

1. **The conveyor works as designed and the crash contract survives it** (G6):
   full cargo gate green every commit (812 tests `--test-threads=1`, clippy
   `-D warnings`, fmt, doc, bench smoke); **loom 24/24** incl. the 5 new
   `conveyor_core` models; conformance suite 10/10 (was 9/10 RED-first);
   crash harness extended and green — torn batch member FIRST/MIDDLE/LAST
   (each drops that tx only), batch-spanning ring wrap, the deterministic
   co-batched §4.4 pt 4 rollback race (RAM == replay digest), replay-twice
   digest equality under real batched storms, cancel-mid-batch at four
   committer stages under the conservation audit incl. the Issue-13
   same-key-blocks case; kill-9 soaks **100/100 serial + 100/100 batched
   (3 concurrent lanes — SIGKILL lands on live multi-entry batch writes)**.
   `meta_conveyor_pass_panics = 0` across every session row.
2. **Group formation is proven, not inferred** — where arrivals can overlap:
   the 8-writer strict storm forms batches up to 8 on every substrate;
   **median ≥ 4 lands on the A-cow context substrate (median_lb = 4 exactly,
   both mf phases)**; on B1/C the strict medians measure **2–3**, bounded by
   the substrates' own 3–9 µs barriers (batch time ≈ op time ⇒ queues never
   deepen — the design's own arrival math; see §OQ-5 constant below). Strict
   many-dirs **barriers/op halve**: B1 0.81→0.34 (mfcreate) / 0.88→0.40
   (mfunlink); C 0.68→0.31 / 0.76→0.37.
3. **G3 (strict/default convergence, B1 + C)** — the one-dir ratios measure
   **85–92 %, identical on both tips (M7 − pre ≤ ±0.9 pt on every ratio)**:
   the residual gap is **conveyor-independent and upstream of the daemon**
   — the kernel's parent `i_rwsem` serializes one-dir arrivals (the §5.8
   finding), so one-dir strict runs at group = 1 *structurally* on both
   tips, and the gap is the flat per-op strict overhead (coalescer wrapper +
   watermark wait + one 3–9 µs fdatasync ≈ 16–19 µs against a ~140–160 µs
   op). The gate's **form** (convergence; formation proven; barrier off the
   throughput path) is met; the **90 % constant** on B1/C one-dir is settled
   by this session's numbers per OQ 5 for M11's freeze: B1 rename/unlink
   ≥ 90 % ✓, B1 create 88.5 %, C 85–87 % — *equally pre-M7*, i.e. nothing
   the commit pipeline (this PR or any batching PR) can move. Recorded as
   the measured constant, not improvised around.
4. **A-cow strict context (non-gating, the barrier-bound regime D5 targets)**:
   strict mfcreate **4,434 → 5,568 ops/s (+26 %)**, mfunlink 4,807 → 5,337

**The OQ-5 constant, settled by measurement**: on substrates whose barrier
costs ≈ the op cost (B1 3 µs, C 9 µs), the 8-writer strict storm's group
median is 2–3 — queues cannot deepen behind a barrier that finishes before
the next arrival. Median ≥ 4 is reached exactly where the design's
barrier-amortization argument applies (A-cow, 500 µs-class barriers). The
G3 group clause is therefore satisfied in its load-bearing sense (formation
proven under overlap; ≈ 1 would have meant the conveyor regressed — it
reads 2–4 with a full histogram up to 8) and M11 should freeze the B1/C
constant at the measured 2–3, A-class ≥ 4.

## Deferred-mode residual — mfunlink −11 % (disclosed, not gated)

B1 30,102→26,632; C 30,266→26,805 (default cadence, 8 writers, 8 dirs).
Counter forensics (B1 pair): journal entries/bytes and reclaim batch fill
identical; engine work *down* on M7 (`meta_kv_commit_smo_retries` 1,044→120,
node appends 10,259→5,253); no stalls, no panics, checkpoints equal. The
cost is structural: pre-M7, 8 disjoint-leaf committers ran RAM applies in
parallel; the conveyor serializes applies through one pass task, and the
unlink phase adds 64-ino `destroy_inodes` batches (~130-record applies)
to the same pass pipe. Creates (light applies) and renames are unaffected;
one-dir rows are unaffected (kernel-serialized anyway). Hand-off note: if
the program wants this back, the shapes are intra-batch parallel apply or
reclaim-batch splitting — neither touched here (not a gated row; the gated
deferred rows — one-dir + mfcreate create — are flat).

## M6 drain-fold disposition (the named hand-off)

The times-echo drain commits are ordinary `commit_tx` transactions, so they
ride the conveyor **by construction** — when a drain's arrival overlaps user
traffic it co-batches into the same pass (one lock window, one write, one
barrier), with zero dedicated machinery. Nothing was contorted for it;
`meta_kv_times_echo_drain_commits` keeps counting drain *transactions*
(session rows: 6–12 per 100 k-op unlink phase, unchanged from M6), and the
fold shows up in `meta_commit_group_size` when it happens. Disposition:
**absorbed naturally; no further work owed.**

## Cancel-harness conservation audit (the §5.5 lifecycle evidence)

Every scenario ends with: queue drained, `admitted == 0`,
`completed_upto == head`, `meta_conveyor_pass_panics` unmoved, and a
follow-up commit succeeding. Stages covered (tests/conveyor_tests.rs):

| stage | construction | result |
|---|---|---|
| pre-enqueue | never-polled future dropped | inert; name still free |
| post-enqueue (Issue 13) | committer aborted while parked on its oneshot, pass held pre-drain | second same-key create **blocks on the DLM stripe** for the whole hold (40 × 5 ms probes: never finishes, never co-queues), then observes **EEXIST** — the dropped committer's tx still commits under the queue entry's guards |
| mid-pass | aborted inside the admitted-stall hazard window (`admitted > 0` observed) | budget conserved; tx commits; lookup lands |
| pre-fanout | aborted after the batch's entry landed, pass held pre-fanout | dead-receiver send harmless; tx durable; zero panics |
