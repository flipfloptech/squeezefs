## Root cause (charter item ii)

One design gap, three faces: **the per-block flush unit never re-validated
its authority — it re-presented state snapshotted at staging time, forever.**

1. **The livelock** (`src/fuse_client.rs`, `run_constant_writeback_worker` →
   `flush_single_active_block` → `flush_one_active_block`): a
   `WritebackRequest` snapshots `fencing_token` at `put_active_block` time
   and the never-lossy ladder (`requeue_or_hard_fail`) re-presents that SAME
   token on every retry. The DLM is process-local and every lease
   acquisition INCRs the ino's generation (`dlm.rs::acquire_lock`), so any
   later open/close on the file (the fsstress grammar) makes
   `save_metadata_to_backend`'s check (`routing.rs:1497`,
   `token < current_fencing`) fail **deterministically** —
   `FencingTokenExpired` cycling attempts 0→3, wrap, repeat at capped
   backoff. The ladder-doc invariant "genuinely superseded units
   (fencing/NotFound) never reach this ladder: the flush unit itself
   resolves them as clean no-ops" was **asserted but never implemented**:
   the unit had no supersession test at all. Incident: 27,479 errors,
   3 unit-generations for one block (tokens 24/28/31 vs expected 35),
   22 hung writes, kill -9 ×2.
2. **The teardown leak** (`flush_one_active_block` removal epilogue): the
   staged-entry removal was keyed on the token the flush **presented**
   (`tok == token`), so the authoritative sweeps that present the *current*
   generation (`flush_all_staged_blocks_to_backend`, fsync's
   `flush_due_active_blocks_for_inode`) could flush an entry stamped under
   an older generation but **never remove it** — `staged_writes_in_flight`
   never drained, `destroy`'s drain-wait spun, and the leaked entries kept
   re-feeding the worker: the force-flush livelock (41,680 errors at
   teardown, kill -9).
3. **The NotFound face** (exposed by this session's churn-amplified 013
   rig, `TIME_FACTOR=10 LOAD_FACTOR=3`: `Io(NotFound "Inode N not found")`
   cycling forever, 48 spins for one ino until process exit): a unit whose
   ino was unlinked+reclaimed after staging fails its merge NotFound on
   every retry (the record is gone; v3 inos are monotonic — it can never
   come back). The strand shape: the staged entry outlives
   `delete_file`'s sweep when the block index is invisible to the persisted
   layout (RAM meta evicted + size extension never persisted).

## Fix design (charter item iii — both invariants preserved)

**Supersession is decided by staged ownership; the merge credential is the
current generation; missing-inode custody is verified-then-discarded.**

- `flush_one_active_block(ino, b, owner_token: Option<u64>, …)`:
  - `Some(T)` (queued writeback units): if the staged entry's stamp ≠ T, a
    newer write re-staged the block — every re-stage pairs with its own
    custody chain (its unit, or the fsync/teardown sweeps) — so the unit
    resolves as the contractual **no-op** (`writeback_superseded_noops`).
  - `None` (authoritative sweeps: fsync family, queue-full fallback,
    dismount force-flush): owns whatever is staged now.
  - The **merge presents the ino's current DLM generation**, read fresh per
    attempt (`flush_one_active_block` + `upload_active_block_bytes`). A
    racing bump degrades to a *transient* `FencingTokenExpired` the ladder
    converges (`writeback_stale_token_retries`) — never a permanently-stale
    snapshot. Cross-node/-mount staleness stays governed where it always
    was: lease acquisition, the foreground write-path fencing checks
    (untouched — a fenced-out writer still must not publish), and
    `recover_staging`'s generation binding ("stale fencing tokens discard
    staged work" is the **remount** contract, not a license to drop live
    acked custody).
  - **Removal keyed on the capture-time staged stamp**, so authoritative
    sweeps drain what they flush → `staged_writes_in_flight` → 0 → bounded
    `destroy` drain-wait.
  - **NotFound merge failure ⇒ verify-then-discard**: an authoritative
    `getattr` re-probe confirms the inode record is truly absent (a flaky
    device/block NotFound keeps retrying — never-lossy), then the orphan
    staged entry is discarded (`writeback_orphan_discards`) — the recovery
    contract's "missing inode meta discards orphan active blocks", applied
    live. No dead-inode resurrection; no NotFound spin.
- `upload_active_block_bytes` also frees its published-but-unmerged block on
  merge failure (same leak rule the `7724bba` fix gave the flush unit).

**Why never-lossy holds (both sides):**
- *Not superseded + stale token* (S == T < generation): flushes acked
  custody to durability under the refreshed credential — pinned by
  read-back + block-map assertions (`stale_token_unit_still_owner…`).
- *Superseded* (S ≠ T): the bytes that matter were re-staged under the
  newer stamp whose own unit/sweep carries the durability promise; the
  newest bytes win (`superseded_unit_resolves_as_noop…`).
- *Deleted ino*: custody is superseded by the delete — the file is gone by
  user intent; discard is the recovery contract's disposition
  (`reclaimed_inode_unit_discards_orphan…` + updated teardown Contract 2).
- The sticky-failure map stays deleted; retry-forever remains the
  disposition for genuinely transient failures (the `1295eab` EIO fix is
  intact — its two ladder tests still pass unmodified).

## Teardown disposition (charter item iv)

Dismount force-flush is now a **draining** authoritative sweep: owner-None
flush + capture-stamp removal + verified orphan-discard means every staged
entry either becomes durable or is provably-superseded discarded — either
way it leaves the ring, `staged_writes_in_flight` reaches 0, and `destroy`'s
drain-wait converges instead of spinning. `tests/dismount_teardown_tests.rs`
Contract 2 re-pinned to the new shape (300 orphans: flushed=300, failed=0,
zero leaked entries, in_flight 0, discards counted).
