## 1. What landed

Under bit 17 the writer that wins the D0 ladder on a volume IS its **manager** (KD-SYM-3 — an ordinary appender with the `is_manager` bit; the fixed ledger stays role-bound to it). It carves **extent grants** for every other appender, takes them back at the checkpoint cadence, answers **`JoinAppender`** over the S8 owner service, and on a PR substrate holds the metadata namespace under **WERO** with every other appender a registrant. With a grant, a declared region's structure — interior flips, allocator deltas — journals into **its own ring**: PR 2's deviation 3 is reversed and PR 2's `Lease` / `Extent` classes are the tripwires. Everything stays **dark** behind bit 17 and the two seams; a bit-17-absent volume is untouched except for two shipped-bug fixes (§6 items 1–2).

### 1.1 Grants (`src/meta_backend/kv/slot_state.rs`, `appender.rs`, `backend.rs`)

- **Durable form**: `extent_grant:{appender}` in tree 0 — the WHOLE grant as normalized runs (`ExtentGrantRecord`, versioned, total decode, ascending non-adjacent runs); the appender's page `grant` runs = the WHOLE UNCLAIMED remainder (≤ `GRANT_RUNS_MAX` = 4 by construction — a remainder in more runs moves its smallest runs to the returnable batch before the page is written, `RegionGrant::trim_to_page_runs`, and a carve is coalesced with the caller's remainder before it is decided; never a truncation recovery would read as claimed — round 2, Issue 9).
- **RAM** (`RegionGrant`): `unclaimed` / `claimed` sets, `pending (extent, gate)` parked on the REGION's tail, `returnable`; claim lowest-first; `free_pending` → `advance_durable(tail)` → `take_returnable` → `ReturnExtents` at the cadence; `recover(record, page)` at EVERY open — a `Free` page names no remainder, so everything the record still names lands CLAIMED, the truth after a clean leave (round 2, Issue 1 — the bug: a non-recovered open built an EMPTY grant against a record naming the region's live images, and every later retirement of a pre-remount image was dropped by `free_pending`'s claimed guard — never parked, never returned, invisible to C13 and the closure gauge; the durable-vs-RAM law `record ⊆ claimed ∪ unclaimed ∪ pending ∪ returnable` is now pinned after every open, `grant_holds`) — then the region ring's in-window `alloc` / `free` fold (`claim_exact` / `free_exact`); a `promised` ledger SHARED with the region's leaves' dirty halves (`NodeDirty::set_promise_ledger` → `RegionGrant::promise_ledger`, `extent_grant_promised`): a leased leaf's §4.7 promise rides the GRANT, never `heap_promised` (Issue 10); closure `granted ≡ claimed + pending + returnable + returned + unclaimed` published as `extent_grant_extents` / `extent_grant_{claimed,returned,unclaimed}`.
- **Sizing**: `grant_extents_derived = clamp(2 × ewma_smo_rate × failover_bound_s, 8, free_heap / (4 × appenders))` — the floor 8 = ≤ 2 extents per compaction/split × 4 pending root swaps per cycle; `SQUEEZEFS_SYM_GRANT_EXTENTS` explicit-wins; tie-tested (`sym_manager_grant_and_failover_bound_derive_from_the_ladder_and_the_smo_rate`). Refill proactive at 50 % (`refill_due`, `grant_cadence`) AND reactive: a flush pass that meets `GrantExhausted` with the manager reachable refills and retries the node once (§6 item 4).
- **The manager's executors**: `manager_extent_grant_class` (`want` CLAMPED to the derivation's cap — `clamp_grant_want`, a wire integer is never an allocation authority; §5.3.5 idempotency: a caller whose unclaimed remainder — an in-process region's RAM grant, a wire joiner's page — already covers the ask is answered it VERBATIM, `manager_verb_replays`; USER class for the cadence and the join, INTERNAL for the flush pass's compactions (Issue 6); claims coalesced with the remainder, alloc deltas + the merged record as ONE ring-0 control entry via `write_control_entry` in the USER admission class (Issue 15 — a verb storm never eats the checkpoint reserve), the page rewritten; a heap that cannot serve one extent answers `NoSpace` — the SPACE class), `manager_return_runs` (the wire form: `validate_return_runs` rejects an overflowing / out-of-volume run before anything proportional to it — `KvError::Rejected`, `STATUS_REJECTED`, `manager_verb_rejected`; the frame's runs are COALESCED first — `coalesce_runs`, sorted and merged, bounded by the frame's own run count — then merge-walked against the record's disjoint runs (`intersect_coalesced_with_record`: strictly ascending, ≤ the record, no dedup step — round 3, the Issue-2 residual: the first build emitted one extent per frame run × record extent before its dedup); what lies outside the record is `already`, counted after the coalesce plus the inner partition's own count so `cleared + already ≡ named` (Issue 19)) → `manager_return_extents` (free deltas at retire 0 + the record rewritten/deleted; an in-process region's RAM grant DROPS the returned extents with the return and REFUSES a CLAIMED one — a live image, Issue 11 — or a PENDING one — its free parked on the region's tail, returnable only through `advance_durable` (round 3, Issue 17; `GrantHeld` names which); a wire joiner's page remainder is rewritten without them), `manager_join_appender` (§1.3). `grant_cadence` per checkpoint: fold the SMO rate, ship returnable batches, refill at 50 % consumption AND below the derived size. `appenders_known` (the directory's Live count, wire joiners included; raised by every join) is the cap's appender term (Issue 12).
- **The stall arm**: `SmoContext::claim_internal` scoped to a region answers `KvError::GrantExhausted` → `SqueezefsError::refused(EAGAIN)` on the commit path; the flush pass DEFERS the node and counts `manager_dependency_stalls` (never `ENOSPC`, never `heap_full`); the heap admission refuses `GrantExhausted` only under the unreachable-manager seam (`test_set_manager_unreachable` — its product successor is PR 4's manager-lease liveness signal, named on the line) — otherwise it admits and the cadence refills (§6 item 5). A FULL heap on a leased slot is the SPACE class, never the manager dependency: the grant answers `NoSpace`, the flush pass's reactive refill carves in the INTERNAL class (compactions — the SMOs that RETURN extents — draw to the compaction floor like the manager's own) for exactly ONE SMO's images (`SMO_IMAGES_MAX` = 4 — a split's ≤ 3 parts + a root; round 3, Issue 18: the first build asked for the full derived grant from the reserve) and defers the node on the space arm; `manager_dependency_stalls` stays 0 (Issue 6).

### 1.2 Own-ring structure (deviation 3 reversed)

`SmoContext` carries `region: Option<SmoRegion { appender_id, ring, grant }>` and a slot → region **resolver**; every SMO entry point (`smo_replace`, `try_merge_node`, `collapse_root_chain`, the lazy mint's `create_inner`) calls `scope_to(self.forest_slot)` first, so the flush pass, threshold maintenance, the merge sweep and the defrag arm can never run a leased slot tree's SMO in the manager's ring by omission. The entry reserves in the REGION's ring (`smo_ring`), claims from the REGION's grant, parks the retired image on the REGION's tail (`free_pending(extent, gate, forced)`). Per-slot dying floors for INTERIOR nodes and root swaps (`NodeCache::note_slot_dying_floor`, `KvTree::note_root_swap_floor`) clamp the region's tail; the checkpoint folds `SlotTrees::unpublished_root_floors()` PER SLOT and every slot-stamped node of a leased slot into that region's live floors. Replay phase 1 of a region ring applies its own interior records (level DESC) and folds its alloc/free deltas into its grant; `detect_appender_violations(rings, leases, granted)` makes an interior record legal for a leased slot and an alloc delta legal inside a grant.

### 1.3 The verbs (`src/meta_ship/manager.rs`)

`ManagerCall::{JoinAppender{identity, ring_want_bytes}, ExtentGrant{appender_id, want}, ReturnExtents{appender_id, runs}}` / `ManagerReply::{Joined{appender_id, page_addr, ring_segments, grant, already}, Granted{runs}, Returned{cleared, already}, Refused{reason}}` in bounded bincode frames (`MANAGER_SCHEMA` 1, the CONTROL class cap inside the body) as ONE verb family `VERB_MANAGER_CALL` on the S8 owner service; **`CLUSTER_WIRE_SCHEMA` 4 → 5** (bumped ONCE for this program's wire — KD-7 same-commit fleets; PR 4+ extend the enum). `ManagerService: RpcAsyncService` decodes, gates the schema, dispatches to the executors and records `manager_service_ns` {admit, execute, reply, total} exact-sum + the ledger (`manager_verbs` / `_per_s` / `_replays` / `_refusals`, `manager_load_pct` = Σ service ÷ wall). Idempotency is the DURABLE witness: a `JoinAppender` re-sent to this manager or to a SUCCESSOR answers `Joined{already}` off the joiner's `Live` page — with the page's UNCLAIMED remainder as its `grant`, never the whole record (Issue 3), and a join the manager died inside (page Live, no grant minted — the seam `TEST_JOIN_HOLD_AFTER_PAGE` pins the window) is COMPLETED by the replay, which mints the owed grant so `Joined.grant` means the same thing on every reply; an `ExtentGrant` whose caller already holds ≥ the ask is answered the remainder verbatim (Issue 4); a return of extents the record no longer grants answers `already`. A frame whose wire integers name what the durable state cannot is REJECTED at the service edge with its own status (`STATUS_REJECTED` = 49, `manager_verb_rejected`) — the buggy/hostile-peer class, kept off the must-stay-0 witness gauge (Issue 2). `manager_join_appender`: the lowest `Free` directory page or the chain grown by one extent (header LAST, then the previous header's `next`, each barriered), a ring of ≤ 8 coalesced extents — ZEROED before any page names them, its position space continuing past the page's watermark and ring 0's head (§6 items 13–14) — (alloc deltas as one control entry), the page `Live` into BOTH directory slots (PR 2's directory-first law), the initial grant; refuses past `appenders_capacity` naming the metadata volume COUNT (R-SYM-6). `ManagerClient::{join, extent_grant, return_extents}` is the caller side. The join refusal at open is narrowed to a `Recovering` page or a foreign `Live` page whose id THIS mount's declared partition claims — a wire joiner's page is a peer.

### 1.4 The role, the fence posture, the registrant ceiling

- **`manager_lease`** = `held` (this mount won the ladder) / `peer:<node token>` (another node's `Live` page 0 — a probe's face) / `vacant` (no forest, no set); **`manager_failover_bound_ms`** = `CLIENT_STALE_TTL_SECS × 1000` + the ladder's measured wall + the replay's measured wall, DERIVED at open, published, ALSO `manager_dependency_stall_bound_ms`. A successor that wins over a dead manager's `Live` page 0 adopts its newer roots at replay (the fixed-ring replay IS the dead manager's ring) and takes the role. `manager_should_release_role(unreachable_ms, T_owner)` is the §5.5.2 decision as one function + the `manager_vol0_unreachable` gauge (PR 8/10 wire the roles).
- **KD-SYM-13** (`decide_meta_fence_posture` at open): a declared partition or a join on a namespace without PR refuses unless `SQUEEZEFS_SYM_ALLOW_NON_PR=1` (announced "detection-grade" at every mount using it); a solo forest mount arms nothing and keeps the shipped rtype-1 posture verbatim.
- **§5.8.1 WERO**: with the plane armed on a PR substrate, `SQUEEZEFS_META_PR_WERO=1` (default) makes the manager's hold rtype 3 (`meta_pr_wero` = 1; `rsv_acquire` / preempt / release rtype-aware) and joining appenders REGISTRANTS (`data_custody::join_wero_as_registrant` — the standing hold one namespace class over); `=0` keeps rtype 1 and is refused on a PR substrate without the opt-in. One identity per mount; no fencing groups, no derived identities, no target-ACL probing. Co-located appenders sharing a registrant are their own guarantee row (KD-SYM-22 — `flock` + `T_self` + the frame screen; `operations.md`).
- **KD-SYM-18/23** (`reservation.rs`): the Reservation Report read is two-step SIZED BY REGCTL (`report_len_for`: header, then `header + 64 × REGCTL`, re-read once if the count grew) on both namespace classes; `parse_reservation_report` is total; the cap is DECLARED (`SQUEEZEFS_PR_REGISTRANT_CAP`) or LEARNED from the device — only from a REGISTER refused by a device-answered NVMe status in the command-specific or vendor-specific class (`NvmeStatusError`, typed on the passthru so callers classify instead of reading a message; never a transport errno — EIO on a path failover, ENXIO on a disconnect, ENOTTY on a still-connecting controller — never a generic, transient or path-related status: `nvme_status_is_transient` enumerates the aborts, Command Interrupted, Transient Transport, Namespace Not Ready, SCT 3), and only when the SAME status REPEATS at the same registrant count (one refusal is a candidate); a REGISTER that later SUCCEEDS at or past the learned count unlearns it (round 2, Issue 5; `learn_registrant_cap`, min; `clear_learned_registrant_cap`); the per-namespace report gauges are keyed by the client's path and updated in place under a poison-tolerant lock (Issue 14); `registrant_cap_gate` refuses a join LOUD at or past it naming the count, the namespace and the remedy (`pr_registrant_cap_refusals`). Gauges `pr_registrants_per_namespace` / `pr_report_bytes` (per device path), `pr_registrant_cap` (0 = unbounded, nvmet's posture).

### 1.5 fsck C13 (`src/fsck.rs`, `KvMetaBackend::c13_orphan_image_extents` / `c13_return_orphan`, `KvTree::reachable_node_addrs`)

An extent an appender's grant holds CLAIMED that no tree root reaches. The census runs under the SMO mutex AND the forest's mint guard (`SlotTrees::mint_guard`), so an SMO's successor before its route flip and a lazy mint's root before the forest names it — the "live in-window image" — are structurally never candidates, and a retired image parked on its tail is a pending-free, not a claim. Its OWN pass beside C8 (unsharded, per volume — the class needs NODE reachability the record census never reads: one paged walk of the interior population per volume, skipped when no grant holds a claim); ONE fresh census per volume in the confirm pass. Repair `return-orphan-image-extent`: the appender FREES the orphan in ITS ring gated on its tail — the SMO retirement shape — and the cadence's `ReturnExtents` clears the bit and rewrites the record; a direct return would have left the in-window `alloc` outside the rewritten record = the `Extent` violation for the next mount. `fsck_repair_classC13`. Empty on a flat volume and an unpartitioned forest.
