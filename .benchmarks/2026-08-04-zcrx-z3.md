## 1. MEM-3 — cancellation safety in the classic lane (closed)

**The bug (spec §2 MEM-3, anchors `src/zcrx_lane/initiator.rs`)**: the
`SendMutPtr` contract ("caller awaits the oneshot before releasing the
buffer") was honored by the timeout arm (abort-and-join) and silently
broken by CANCELLATION: a dropped requester future left
`Pending{dest,tx}` in `shared.pending` while the pooled buffer recycled
under the reader task's captured span pointer (recycled-buffer write),
and the op's CID — returned only on the normal exits — leaked: after
`queue_depth` cancellations the pool was empty (`CID pool exhausted
(permit/pool desync)`) and the lane degraded to the kernel path for the
mount lifetime. The area lane shared the CID-leak face (its dest is
requester-gathered, so no recycled write there).

**The fix (custody, not ceremony — cancellation-safe by construction)**:

* `CidSlot` (RAII): CID + owned depth permit live in the PENDING ENTRY,
  never the requester. Custody returns exactly when the driver destroys
  the entry (completion / send-failure cancel / poison drain). A
  dropped future leaks nothing; gate and pool cannot desync.
* Classic entries own a destination keep-alive: `read_into_pooled`
  (the funnel's arm) hands a clone of the pooled `Bytes` into every
  segment's entry; `read_into_slice` bounces through an op-owned
  allocation. The reader writes only destinations whose entries exist
  ⇒ the pool can never recycle a buffer a lane context can still
  write. `read_into_ptr` keeps a documented raw contract (caller-owned
  lifetime past cancellation; area backends meet it trivially —
  requester-side gather, a dropped future gathers nothing).
* Area admission permits ride `PendingFill` → `ZcrxFill` (released
  after the requester's gather, or inside the dead completion channel
  on future-drop) — accounting exact under cancellation.
* Drain discipline: `poison(drain=true)` only where the destination
  writer provably writes no more (reader/driver exiting, or
  abort+JOINED by the timeout arm); writer-side failures poison flags
  only (waiters resolve via their own bounded timeouts — never a
  keep-alive dropped under a live reader).

**Deliberate deviation, stated**: the spec's minimal prescription was a
drop guard doing "the same poison + abort/join the timeout arm does" +
CID return from the guard. Implemented instead: entry-owned custody
with **cancellation NOT a poison event** — poisoning on every dropped
future would rot the `zcrx_lane_poisoned` must-stay-0 tripwire the D5
default-on gate keys on (routine future-drops would disarm the lane).
Same acceptance met (no recycled-buffer write, no CID leak — the
contract suite asserts both), lane survives, tripwire stays honest. A
sync `Drop` also cannot JOIN an aborted task, so the prescribed shape
could not actually close the in-flight-poll write race without this
custody anyway.

## 2. Z3 — gather fusion (the PERF-1 win, local half)

Z2 completed fills as refcounted area-span scatter lists and paid ONE
userspace gather into a pooled bounce — pass-count-neutral vs the
kernel RX copy by design ("do not adjudicate the lane on Z2 rows").
Z3 deletes the intermediate on the shapes that carry a destination:

* **Fused arm**: `dest_addr` funnel reads (the routing raw full-block
  DMA leg — the EXA-class cold-read shape — and the R3 ranged
  zero-copy leg) are lane-eligible via
  `LaneSession::read_into_dest`: each sub-command's completion gather
  lands DIRECTLY in the registered dest. Pool bounce + upstream serve
  copy: gone on these shapes. Dest-less pooled reads keep the Z2 shape
  by design (§4.4 — memory that outlives the serve).
* **Area-backend-only by law** (`dest_serve_eligible`): the classic
  backend's reader writes dests from a foreign task — the MEM-1 hazard
  class for registered ent/arena memory under cancellation. Area
  backends gather on the REQUESTER (post-fill, same poll) — strictly
  safer than the kernel dest arm's in-flight DMA. Classic
  ineligibility is not a fallback.
* **New gauge** `zcrx_dest_gather_bytes` (stats inode): the fused
  SUBSET of `zcrx_gather_bytes`. Engagement law: a fused row must
  account its dest-read bytes here; `gather − dest_gather` = remaining
  two-pass traffic. `gather ≡ fill` closure unchanged.
  `read_dest_dma_bytes` at the routing call sites keeps counting
  dest-leg bytes (copy-ledger closure unchanged); the lane gauge
  separately attributes the CPU pass — field ledger rows subtract.
* **Z2 laws preserved, contract-pinned**: poison lattice untouched,
  R5 Red arm gate untouched, `SQUEEZEFS_ZCRX_LANE=0` kill switch
  first-gate, kernel path byte-identical when unarmed (all Z3 code is
  behind the env/arm gates), per-op fallback into the SAME dest
  (idempotent; partial gathers overwritten), `zcrx_fill_fallbacks`
  honest.
* **No grant-ledger/ordering change**: the fusion re-points the gather
  DESTINATION only. Nothing new for loom to model (task law:
  "loom any grant-ledger/ordering change" — none occurred).

## 3. Microbench (mandatory) — the fused-path delta

`benches/zcrx_bench.rs` `zcrx_gather` group (sim venue — real mapped
area + ledger-refcounted `AreaSlice` spans, no NIC; both legs
cached-copy: the serve NT floor is 256 KiB and this pair isolates the
PASS-COUNT delta — NT policy is priced in `copy_path_bench`).
`ZcrxFill::from_parts` is the bench/contract constructor.

Dev box, same-process A/B, criterion 100-sample medians — SAME-BOX
RELATIVE numbers per the baseline law (thermally-capped box):

| shape | Z2 two-pass | Z3 fused | delta |
|---|---|---|---|
| 128 KiB (32 page-grain spans — MDTS-face sub-command) | 6.95 µs, 17.6 GiB/s | 4.14 µs, 29.5 GiB/s | **−40.4 % ns/op** |
| 4 MiB (1024 spans — EXA cold whole-block raw-dest leg) | 707.8 µs, 5.5 GiB/s | 180.0 µs, 21.7 GiB/s | **−74.6 % ns/op** |

The 4 MiB two-pass leg pays the LLC-exceeding bounce round-trip (wide
CI on this box — 553–874 µs; the delta is far outside it). The fused
shape is the one the −65–68 % RX CPU Phase-1 upper bound projects onto
at the FS level; the FIELD rows (below) adjudicate the realized win.

## 5. Amendments to the Z2 field acceptance script (Z2 note §5)

The reformat-window bracket in `.benchmarks/2026-08-04-zcrx-z2.md` §5
runs as written, with these Z3 amendments:

1. **Step 2 (engagement closure) gains the fused gauge**: on the cold
   sequential rows, `zcrx_dest_gather_bytes` must account ≈ every
   dest-leg lane byte (the raw full-block leg dominates EXA-shape cold
   reads; `zcrx_gather_bytes − zcrx_dest_gather_bytes` ≈ the pooled
   minority). A Z3 row with `dest_gather ≈ 0` is running the Z2
   two-pass shape — INVALID for fusion adjudication.
2. **Step 3 (A-B-B-A) re-arms as the Z3 CPU bracket**: the Z2 caveat
   ("parity-class throughput… do not adjudicate the lane on Z2 CPU")
   is RETIRED — the fusion is in; RX-side CPU (mpstat) + DRAM B/B
   (uncore) vs `SQUEEZEFS_ZCRX_LANE=0` now adjudicate against the
   Phase-1 −65–68 % projection, sustained ≥ 60 s rows included.
3. **Step 5 (failure lattice) adds one cheap leg**: kill a lane TCP
   connection mid-COLD-row with dest-leg traffic in flight — expect
   the same ONE `zcrx_lane_poisoned` transition, zero failed reads
   (kernel path serves into the same dests), and
   `zcrx_fill_fallbacks` accounting only the in-flight ops.
4. **New cancellation spot-check (MEM-3, cheap)**: during a loaded
   read row, interrupt/kill a reader process mid-flight (^C an
   elbencho worker); expect `zcrx_lane_poisoned` = 0, no CID
   attrition (steady-state throughput unchanged after the kill), and
   a clean unmount. Cancellation is NOT a poison event — any poison
   transition here is a regression against the MEM-3 contracts.
5. Everything else (arm proof, steering fidelity via per-queue
   `rx*_bytes`, loaded soak, NIC-state restore) runs verbatim.
