`kv_node` and `kv_superblock` hold 2-file corpora by construction: both
are checksum-gated whole-sector grammars a blind fuzzer cannot get past
without a re-stamp arm (`kv_bset` has one and grows to 111), so their
90 s buys the reject ladder only — the `verify_node_extent` walk past the
header is reached by the proptest mirror's constructed images, not here.
Growing them a re-stamp arm is a follow-on, not a 1.2 blocker.
`cluster_wire_frame` is the slowest target (11 k exec/s) because every
constructive input pays three HMAC-SHA256 session-key derivations and six
frame MACs — deliberate: the MAC path IS the surface.

## Find #1 — `cluster_wire::hex_decode` panics on a non-ASCII secret (product)

`cluster_wire_frame`, **414 executions in**, artifact `3a d7 96 00`
(`:` U+05D6 NUL — 4 bytes, even, byte index 2 inside the character):

```
panicked at src/cluster_wire.rs:604:39:
end byte index 2 is not a char boundary; it is inside 'ז' (bytes 1..3 of string)
```

`hex_decode` walked its input two BYTES at a time as `&s[i..i + 2]` — a
`str` slice. Its callers are `job_wire::cluster_secret` and
`membership::cluster_secret`, which decode the `job:enroll` record's
`secret` — **on-disk metadata** (class 1 of TEST-4's three surfaces: anyone
who can write the volume controls it, and a torn/misdirected write produces
arbitrary bytes). The release profile is `panic = "abort"`, so a corrupt or
tampered xattr whose secret held one multi-byte character at an odd byte
offset **aborted the daemon** at its first job-wire or membership
enrollment — in a function whose documented contract is "`None` on any
non-hex input". The same walk used `u8::from_str_radix`, which accepts a
leading sign: `"+f"` decoded to `[0x0f]`, a form `hex_encode` never produces
(a parser wider than its encoder).

Reach on the WIRE is nil today (no `RpcFrame` field is hex-decoded on the
receive path — the proof MAC is compared as a string by `mac_eq`), so this
is a class-1 finding, not a remote one.

Repro-port `4c4ad7ab` (RED against the shipped decoder): the artifact +
the sign forms as a unit test (`cluster_wire_hex_decode_is_total_and_exact`)
and the law as a proptest over arbitrary Unicode
(`cluster_wire_hex_decode_never_panics` — it reproduced independently; its
shrunk case `"A𖭽a   aaጘ00a "` is in the regressions file). Fix `754f9c40`:
decode by `as_bytes().chunks_exact(2)` with an explicit nibble alphabet — no
`str` slicing, no `from_str_radix`. Re-run of the target on the fixed
binary: 1.04 M execs, 0 crashes; the artifact executes clean.

## Harness correction (not a product finding)

`kvmap_record`'s first draft asserted `head.gen != 0` on every accepted
head; `kvmap:1` legitimately parses to `gen = 0` (ABSENT — the pre-belt
byte-identity law). The string-exact round-trip already proves an explicit
`;gen:0` is refused (it would re-encode without the segment), so the
assertion became `!candidate.contains(";gen:0")`. Recorded so the next
reader does not mistake it for a product change.
