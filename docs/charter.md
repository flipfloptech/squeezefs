# SqueezeFS-Zig — Build Charter

You are the principal engineer building **SqueezeFS**, a high-performance distributed POSIX filesystem for Linux, from scratch in **Zig**. You are given its complete architecture below. Your job is to implement it faithfully: the same goals, the same mechanisms, the same invariants, the same measured derivations. Where this charter states a law, it is a requirement. Where it states a number, that number was measured on the reference implementation and is the bar you must meet or beat. Nothing below is dogma except the first non-negotiable: a mechanism holds its slot on measured evidence and may be displaced only by a counted A/B that proves something faster at the relevant shape on target hardware — never by convenience, never to make a test pass.

The canonical copy of this charter is `docs/zig-rewrite-charter.md` in the reference repository (`~/Source/squeezefs`, mounted read-only in the build container); this file tracks it verbatim apart from this paragraph. The reference implementation (Rust) lives there too — consult it for exact derivations, knob tables, gauge names and test contracts.

---

## 0. Mission in one paragraph

A FUSE client daemon on every node mounts a shared **volume set**: one or more **metadata volumes** (block devices holding a copy-on-write typed key/value store, "MetaLV") and one or more **data volumes** (local NVMe or NVMe-oF namespaces holding striped 4 MiB blocks). Every read-write mount is an **equal metadata writer** (the GPFS shared-disk model): it appends directly to the shared metadata volumes into trees it leases, journals into its own recovery log, allocates data blocks from ranged grants, and DMAs directly to the shared data devices. No separate lock server, directory service, or database exists; the volumes are the coordination plane. The design target is 10,000–15,000 simultaneously mounted clients all reading and writing, rarely the same files. Every number at that scale is arithmetic on measured constants and must be labelled as such.

## 1. Non-negotiables

1. **Performance is the only terminal requirement.** "The goal is the absolute fastest we can be." Saturation testing is the correctness crucible: load-dependent hangs are first-class product bugs.
2. **Linux only; io_uring everywhere the kernel can do it.** FUSE request hot path = FUSE-over-io_uring, required (mount fails if it cannot arm). Block I/O = io_uring workers with fixed files. Ad-hoc local file I/O = an io_uring file layer. Never reintroduce classical `read/write/pread/pwrite` or `/dev/fuse` polling to dodge a bug; fix the uring path or fail loud. Exceptions by design: TLS/TCP network stacks; staging **mmap** segments (zero-syscall get/put); the app↔daemon interception hop (shared memory + futex — adding an `io_uring_enter` per side would be slower).
3. **Zero-copy, latch-free hot paths.** No blocking mutex/rwlock on the primary read/write data path; hot tables use lock-free structures (sharded clock rings, atomic refcounts, concurrent hash maps, arc-swap-style immutable snapshots). The large-write hot path is **1 userspace copy + 1 DMA** (the zero-copy path is 0 + 1). Never NT-store a destination a CPU reads next.
4. **Portable by default.** No CPU-model code paths, no per-CPU tuning tables. Microarchitecture-sensitive code must be a measured win across the hardware set, derived from runtime behaviour, and harmless where absent. NUMA-aware code must scale over arbitrary domain counts (distance-based locality, never "2 sockets"). Kernel version is NOT portability — a custom kernel is a first-class product surface; kernel-dependent fast paths probe, negotiate, and degrade loudly on stock kernels.
5. **Every constant is DERIVED.** Sizing defaults are functions of the memory budget, core count, block/ring geometry, or measured rates — never free-floating byte/thread constants. A fixed clamp needs a documented physical/format/kernel/measured reason on the line. Floors are legitimate only as physical minima or "never regress below what shipped." Every derivation has a drift-is-red tie test. Env overrides: explicit wins verbatim; precedence absolute > percentage > derived.
6. **One knob convention.** Every `SQUEEZEFS_*` env knob is in a registry (name, kind, admissible range, default, purpose). Absent = unset/empty/whitespace; booleans `1/true/yes/on` vs `0/false/no/off`; integers have an admissible range and out-of-range REFUSES (never clamps). A malformed/retired knob refuses the process at startup naming every offender. An unregistered knob name is announced as a probable typo. A build-time convention test fails on any unregistered knob literal. Knobs are classified: delete / `SQUEEZEFS_TEST_*` (seams) / measurement A/B levers (logged at mount when non-default). The user never chooses a data path; a wrong path outcome is a bug, not a posture.
7. **Forward-only on-disk/wire format.** No backward compatibility. Unknown incompat bits refuse the mount loud ("reformat required"); unknown wire schema refuses. Old binaries refuse new volumes loud. Capability bits mean one complete thing each.
8. **Fail loud, never silent.** Must-stay-0 tripwire counters for every "cannot happen" (the runtime equivalent of a debug assertion that must never panic a handler and lose a reply). Fail-stop lattice: repeated journal-barrier failure or a device fence latches the volume FAILED (EIO until remount). Never a silent fallback to a weaker posture.
9. **No dead code.** Delete unused code; never suppress it.
10. **Zero synced-data loss** on any single-node `kill -9` at any instant **and on a power cut** (amended 2026-10-19, the owner's ruling, decision 0002 row 549: a synced write is on STABLE STORAGE before its fsync / fdatasync / syncfs returns — a STAGED file's bytes included — amended 2026-10-21, decision 0002 row 551: the staging ring is the write cache in RAM, so the fsync's staged leg PROMOTES the resident to the data volumes, its block flushed, before the meta barrier that makes the layout naming it durable; the 65 dm-flakey rows of xfstests are the oracle), and an acknowledged unsynced write lost only within its bound `T_wb` (amended 2026-10-14, decision 0003 §AJ — the owner's ruling: close is no durability point; an unsynced write leaves daemon memory within `T_wb`, a synced one before its fsync / fdatasync / syncfs returns; a crash never tears a write: each acknowledged one is whole or absent — zeros, or past the last durable length — and never another file's bytes; a size never becomes durable before the bytes it makes readable, so an unsynced extension's size follows its landing by one times drain — decision 0003 §AL.5, ext4's `data=ordered`); metadata whole-transaction atomic and torn-write immune on ANY device including plain files; fsck clean after every kill. **Metadata takes the Lustre/ext4 posture (amended 2026-10-20, the owner's ruling, decision 0003 §BB):** a metadata op is acked once applied in RAM and becomes durable at the next commit; `fsync` / `fsyncdir` / `syncfs` make it durable on return. A DAEMON crash stays lossless: the journal's not-yet-landed entries live in a kernel-held memfd (the journal tail) that outlives the daemon, and its supervisor replays them to the device before the writer claim is released — and HOLDS them, should the device refuse the replay, until one lands (amended 2026-10-24, decision 0003 §BR); only a true power cut has the flush-window exposure — at most `SQUEEZEFS_META_FLUSH_INTERVAL_MS` (50 ms derived; 0 = strict, durable at the ack) of un-fsync'd metadata, ext4's posture with a 100× tighter window (its commit interval is 5 s).

## 2. System shape

```
                 ┌──────────────────────────────────────────────────────┐
  applications ─►│ FUSE client daemon (one per mount)                   │◄─ LD_PRELOAD shim / SDK
                 │  FUSE-over-io_uring transport · per-core handler lanes│   (shared-memory ring, bypasses kernel FUSE for data ops)
                 │  routing by layout · tiers · write/read pipelines     │
                 └──────────┬───────────────────────────┬───────────────┘
                 metadata + leases + tokens         block data I/O (io_uring, O_DIRECT)
                            ▼                                   ▼
            ┌──────────────────────────────┐    ┌──────────────────────────────┐
            │ Metadata volumes (MetaLV)    │    │ Data volumes (NVMe / NVMe-oF)│
            │ CoW typed-KV btree forest    │    │ 4 MiB striped blocks         │
            │ per-writer journal rings     │    │ packed small-file blocks     │
            │ slot leases · tree 0 control │    │ PR-fenced (WERO)             │
            │ claims · jobs · membership   │    │ per-volume allocation bitmap │
            └──────────────────────────────┘    └──────────────────────────────┘
```

**One law:** a node appends only to slot trees it leases, journals only into its own ring, allocates only from its own grants, and runs every structure modification of its trees itself. Everyone else reads those trees' objects under tokens the lessee grants and recalls.

Lock order (never invert): (1) per-inode FUSE op guard → (2) per-inode lease lock → (3) per-(inode, block) flush lock → (3.5) per-inode block-map meta stripe (4096-way; never held across a terminal block free) → (3.7) the data plane's per-inode layout lock (4096-way; every layout-record read→stage→commit — a block-map publish takes it inside the upload's (3.5), a staged promotion takes (3.5) then (3.7), the filesystem's truncate takes it before its 4a set; never held across a terminal block free) → (4a) metadata object locks `I{ino}` / `D{parent,name}` (striped, derived width `next_pow2(max(4096, 16 × cpus × q_depth))`; one canonical multi-key acquisition per volume per op, taken holding no other 4a guard; one sanctioned try-only out-of-order addition) → (4b) KV leaf node write locks (commit path: leaves only, ascending node address, deduped, lock-revalidate-retry; interior locks belong to the serialized checkpoint/SMO task, parent-then-child; never held across device I/O or ring-space waits) → (4c) journal reservation (a wait-free atomic, not a lock). Never hold (3.5) and then acquire (1) or (3). Never hold a pooled metadata handle across durable device I/O.

## 3. Platform and the custom kernel

Target: Linux ≥ 6.14 for FUSE-over-io_uring (`fuse.enable_uring=Y`, which the daemon writes itself BEFORE replying to INIT — since 7.2.4 the ring is created at INIT-reply time iff the parameter reads Y then). The product tracks the latest mainline.

**The sqz kernel series** (a maintained patch set; ship its recipe as a containerized, pinned build): the FUSE/io_uring kernel-managed buffer ring + zero-copy series — upstream REJECTED that form and 7.3 shipped buffer pools + per-file zero-copy instead (amended 2026-10-21, decision 0003 §BE: the daemon speaks mainline's UAPI as its primary rung, §4; the kmbuf patches 0001–0021 and 0024, 0026, 0030, 0031 are transitional, their deletion an owner-ruled commit once the mainline rung matches their numbers; `scripts/kernel/patches-mainline/` carries the fixes and proposable patches on v7.3) — plus authored patches:
- **kmbuf buffer rings** (`FUSE_URING_BUF_RING`): payload is a kernel address; deletes the per-4 KiB lock→GUP→unlock term (measured 12.8 % + 2.6 % of client cycles).
- **FUSE zero-copy** (`FUSE_URING_ZERO_COPY`, CAP_SYS_ADMIN): the app's request pages are installed in the daemon ring's sparse fixed-buffer table at delivery; paged replies move through `READ_FIXED(fd → slot)` (device fd on the direct leg, a memfd bounce otherwise); paged WRITE payloads arrive as a fixed source buffer the daemon can `WRITE_FIXED` straight to NVMe.
- **Abort-race folio references** (page refs follow the io_uring registration lifetime; a release callback frees them when the last rsrc node drops).
- **Payload retention** (`FUSE_URING_PAYLOAD_RETENTION`, `COMMIT_RETAIN`, `RELEASE_PAYLOAD` opcode 3): a COMMIT may end the request (write(2) returns) while the zero-copy slot stays registered until the daemon's RELEASE — the ACK-early accelerator. Negotiate by opcode PROBE (RELEASE with an impossible id: ENOENT ⇒ supported). Stability law: page-cache folios are sound after ACK (a later modification is a new write); O_DIRECT/GUP pages are NOT — snapshot before ACK-early.
- **`FUSE_TIME_LIMITS`** (init flag bit 62; `time_min/time_max` carved from unused init-out bytes): the daemon advertises its i64-nanosecond timestamp range so the VFS clamps where the daemon does.
- **Per-queue FUSE background accounting**: each uring queue gets its own `num_background/active_background/bg_blocked/bg_waitq` under `queue->lock`, budget `max_background / nr_queues` (+ remainder to low qids, floor 1); neither uring path takes the connection-wide `bg_lock`. Measured: queue worker −18 % µs/op, spinlock slowpath 12.8 % → 0.11 %, rand-4k +9 % IOPS.
- **Host-scoped NVMe fabric subsystems** (`nvme_core.fabrics_host_scoped_subsystems`, opt-in, boot-scoped): fabric controllers group by `(subsysnqn, hostnqn)` so two per-mount identities on one host do not merge under one multipath head (which would void per-mount PR fencing).

**Capability discipline:** every kernel feature is PROBE-detected at runtime (e.g. the kmbuf register opcode pair differs per kernel track — resolve by a probe ladder that reads Present only on the full signature: register 0, repeat EEXIST, mmap at the ring offset succeeds), never by kernel version. Post-probe refusals fail the mount loud; the probe is the only degrade point. Two strata only: stock-graceful and full sqz kernel.

## 4. The FUSE-over-io_uring transport (your own FUSE library)

Write the FUSE library yourself (no libfuse on the hot path). It owns `/dev/fuse` INIT, the ring transport, notify writes, and the request/reply codec.

**Bring-up (ordered):** mount → classical INIT read (via io_uring Readv) → build the INIT reply: always `FUSE_OVER_IO_URING`; `FUSE_INIT_EXT`; echo `FUSE_TIME_LIMITS` if offered; never advertise `FUSE_POSIX_LOCKS`/`FUSE_FLOCK_LOCKS` (POSIX advisory locks stay kernel-local — the kernel's `posix_lock_file` arbitrates per mount, giving full semantics for free); `FUSE_HANDLE_KILLPRIV_V2` where offered (the daemon owns suid/sgid/caps clearing: suid always, sgid iff group-exec, caps xattr drop); **`FUSE_EXPORT_SUPPORT`** (amended 2026-10-23, the owner's ruling: file handles are in scope — `name_to_handle_at`/`open_by_handle_at` survive a cache drop and a cycle-mount, xfstests generic/426, 467, 477, 756, 777; advertised iff the filesystem declares it serves the kernel's export operations, `Filesystem.export_support`): the kernel packs `(nodeid, i_generation)` into every handle and, once the inode left its cache, decodes it with `LOOKUP(nodeid, ".")` — answered for ANY inode kind with the inode's attrs and the set's ONE entry generation (the set uuid folded to the kernel's u32, never 0; the root's 0 as the kernel demands; inos are never reused, §5.3, so one generation per set keeps `(nodeid, generation)` unique for the set's life and a handle from a previous format of the same device answers ESTALE), a corpse at nlink 0 ENOENT (the handle died with its last name); a directory handle is reconnected to the root with `LOOKUP(dir, "..")` per hop — answered from the directory's DURABLE parent record (`system.squeezefs.parent`, §5.1: the LOGICAL parent, a striped directory never its stripe; written by mkdir in its own transaction, moved by every rename that changes it; the root's `..` is itself; a non-directory's is ENOTDIR); the RAM `..` memo is a cache of the same fact; zero-message opens for regular files — OPEN is answered ENOSYS, the kernel latches `no_open` for the connection (the daemon opens its own `.stats` once before it reports ready) and opens and releases every regular file locally (no OPEN, no RELEASE; OPENDIR stays), `FUSE_ATOMIC_O_TRUNC` is not echoed so an O_TRUNC open is the kernel's SETATTR(size 0), a CREATE's reply carries no `FOPEN_NOFLUSH` (amended 2026-10-14, decision 0003 §AF; the control arm `SQUEEZEFS_FUSE_NO_OPEN=0` serves OPEN with `FOPEN_NOFLUSH` on clean handles); negative-entry replies (nodeid 0 + entry_timeout); `max_readahead` echoed verbatim → **resolve transport geometry BEFORE serializing the reply** → write `fuse.enable_uring=Y` (since 2026-10-21 also BEFORE `mount(2)`: the INIT offer's bits are the parameter's value when the kernel sends it) → reply → start one drain-group worker thread per group, each with its own io_uring (SQE128, `SINGLE_ISSUER|DEFER_TASKRUN|TASKRUN_FLAG` where buildable), fixed files `[fuse_fd, wake_eventfd]`, (MainlinePool) the queue's pool region registered at index 0 and, on the queue's first ring, `ADD_QUEUE` + `ADD_BUFPOOL` answered inline before any REGISTER, (kmbuf/zc) registered header buffer + kernel-managed buffer ring, a payload arena, one REGISTER per entry per member queue + one level-triggered PollAdd on the eventfd → the arm barrier counts SUBMISSIONS not completions (a REGISTER completes only when it delivers a request; the kernel routes to the ring only once every queue holds ≥ 1 entry) → session ready → hot path over-uring. A refused REGISTER backs off (1 ms doubling to 128 ms, 8 attempts) then retires; the session fails when every entry retired.

**Geometry (derived once):** `nqueues` = kernel possible CPUs (qid == CPU id, which NUMA placement keys on; fewer queues never becomes ready). `max_write = clamp(max(block, 1 MiB), max(page, 4096), max_pages_limit × page)` with `max_pages_limit` from `/proc/sys/fs/fuse/max_pages_limit` (fallback 256); `max_pages = ceil(max_write/page)`; `payload_sz = max(8192, max_write, max_pages × page)` — the exact kernel mirror so REGISTER acceptance is structural. Depth: `clamp(cap / (nqueues × payload), 4, 32)` with `cap = mem_budget/8` (no fixed ceiling); if depth 4 overflows, degrade `max_write` page-aligned toward the 1 MiB base, never below (desired 32 = the measured-best; floor 4 = the shipped posture). `max_background = clamp(nqueues × depth, 64, u16::MAX)`, congestion = ¾ of it. Publish `transport_{queues,q_depth,payload_buffer_bytes,max_background,max_write,max_pages,max_readahead}`.

**Drain groups:** partition qids by NUMA node MEMBERSHIP (never contiguity), width per node = `max(node_cpus/4, 1)` (measured: width 8 on 32 CPUs halved drain cost at IOPS par; one context per CPU paid a thread wake + a ~1-commit enter per op); kmbuf/zc and MainlinePool sessions keep width 1 (registration is per ring per queue); several rings per queue (3 derived) need patch 0030 on the legacy rungs and no patch on MainlinePool (the pool is user memory every ring registers at the same index). Worker thread names `sqz-fuse-ur<qid>`.

**Per-entry slot state machine** (owned by the worker thread; other threads address a slot by value `(qid, ent_idx, commit_id)` carried in the request): `Registered → Delivered{unique, commit_id} → Replied → Delivered…`; `Delivered → Parked` (reply while a payload lease is live) `→ Replied`; `Delivered/Parked → Retained → Replied` (RELEASE); `Retired`. **Law: for every request delivered on a slot exactly one COMMIT_AND_FETCH carrying a reply or a synthesized error is submitted before the slot leaves Delivered** — a lost reply is an uninterruptible-sleep hang and `umount` EBUSY; every non-reply exit routes through a `fail_ent` that commits a header-only `-errno`. A stale/foreign commit id is refused loud; an oversize reply commits header-only `-EIO`, never a truncated body.

**Delivery:** read `fuse_in_header ‖ op_in` + `payload_sz` + `commit_id`. FORGET/BATCH_FORGET are auto-committed with an empty reply after nlookup accounting. **FUSE_WRITE payloads are a zero-copy LEASE** over the registered payload buffer (refs 0→1); every other payload is copied. **READ dispatch law at the delivery CQE:** (a) serve inline if the filesystem's try-only warm ladder answers (per-inode try-lock → active buffer → staging ring → hot tier → read-lane hold → NVMe read cache), (b) else on a zc session at or under the fusion ceiling (`payload/8`, default OFF by measurement) fuse onto the worker's lane, (c) else hand directly to the handler lane homed on the queue's CPU. Partition law: `fast_dispatch_serves + fusions + demotes ≡ READs`. The reap thread never blocks on any arm. **Handler dispatch law:** a namespace or attribute request's handler runs on the worker's own DRIVEN lane (no thread of its own: the worker's pass runs it, its wake eventfd is read by a standing READ on the worker's ring), so it never crosses a thread and its reply is a same-thread commit; the data class (READ demotes, WRITE, the syncs, RELEASE, a FLUSH the worker's try-only custody probe declined under zero-message opens, a truncate, FALLOCATE, COPY_FILE_RANGE, LSEEK, IOCTL, POLL, the locks, BMAP, the forgets) goes to the handler lane homed on the queue's CPU — its device waits park the calling thread, and the worker never waits on a device.

**Payload lease + commit gate (model-checked):** per entry `refs` + `parked`. Last payload ref drop: `fetch_sub(release); fence(seq_cst); if parked → wake worker via eventfd through the coalescer`. Commit gate: `refs == 0 → Ready; else parked = true; fence(seq_cst); re-read refs → 0 ⇒ commit now, else Parked`. Both SeqCst fences are load-bearing (release/acquire alone permits skip-wake ∧ park = a deterministic hang at depth 4). Leases ≥ 1 s count `transport_lease_overlong` and log — never panic. Closure: `parked_commits ≡ unparked_commits` at quiesce. A lease never escapes the handler; a leased buffer is never re-posted or written (shutdown commits header-only for a still-leased ent).

**Reply submission:** publish the commit message, arm the wake coalescer, write the eventfd only if arm returned true (N publications between passes cost one write; `transport_wake_{writes,elided}` — ratio ≈ 1 under saturation = regression). `submit_reply_fd_body(fd, off)` lets a zc worker bridge `READ_FIXED(fd → slot)` from a MAP_SHARED fill pool with no bounce copy. `submit_reply_prefilled(n)` = header only (bytes already landed via the direct device leg).

**Worker pass:** drain eventfd to EAGAIN iff a wake CQE was seen or a producer is armed → disarm (drain → disarm → scan, the model-verified order) → pump pending messages into SQEs with eager non-blocking GETEVENTS flushes, mid-pass reap of finished bridges, then pump the driven lane (disarm → inbox → timers → the fibers ready at entry) and route what they published through the gate in the same pass, then poll ONE fused handler → route commits through the per-entry gate → unpark scan → re-arm both standing READs (the ring's wake, the lane's) → a runnable fiber or a same-thread publication is work in hand → compute a **100 ms park backstop** iff the fused lane is non-empty OR any zc bridge is pending OR the group owes any reply (field captures proved wake chains lose exactly one wake under load) → work in hand ⇒ non-blocking flush and loop; else ONE `io_uring_enter` carrying every SQE and the wait (unbounded only when idle and owing nothing). Tick rescues are counted (`transport_park_tick_{commit,cqe}_rescues` ≈ 0). Commit BATCHING: pushes only append to the SQ; the loop-bottom enter flushes (31 → 9 `io_uring_enter` per create). SQPOLL is a knob, measured not recommended.

**Sideband:** a dedicated classical session on `/dev/fuse` (io_uring Readv) services FORGET/INTERRUPT/resends/switch-over stragglers forever, and carries notify writes (`FUSE_NOTIFY_INVAL_INODE`, `FUSE_NOTIFY_PRUNE`).

**Buffer-mode lattice (amended 2026-10-21, the owner's ruling, decision 0003 §BE):** `MainlinePool` (the PRIMARY contract: mainline's buffer-pool UAPI, Linux ≥ 7.3 — one user pool per queue handed over by `ADD_QUEUE` + a REGISTERED `ADD_BUFPOOL` and registered at one fixed index on every ring of the queue, `IORING_URING_CMD_FIXED` on every REGISTER and COMMIT, the request's payload at the header's `offset` into the pool, zero-copy as a per-queue flag with the app's pages installed at the entry's own `ent_zero_copy_buf_index` and stated per delivery by `FUSE_URING_ENT_ZERO_COPY`, the kernel's copy skipped for READ and WRITE alone) / `UserEnts` (stock) / `BufRing` (kmbuf) / `ZeroCopy` — the last two TRANSITIONAL: the 7.2-sqz series' UAPI upstream rejected, kept until the mainline rung matches their numbers on 7.3, their deletion an owner-ruled commit. The probe of the mainline rung is INIT's `FUSE_HAS_IO_URING_BUFPOOL` (the daemon writes `fuse.enable_uring=Y` BEFORE `mount(2)` so the offer is complete on the first mount after boot); it ranks above the kmbuf ladder; the legacy command probes (opcodes 3/4 = mainline's `ADD_QUEUE`/`ADD_BUFPOOL`) are sent only on a legacy rung. Under zc (either stratum), paged reply bodies must move through the slot via the direct device leg (cold + passthrough + 4 KiB-aligned: DMA straight into the app's pages) or the memfd bounce leg; paged WRITE payloads are HELD in the slot and dispatched before extraction so the handler can `WRITE_FIXED(device ← slot)` (the sole-owner patch class) or lazily extract; on `MainlinePool` a WRITE the kernel copied into the pool is held in its pool buffer the same way (`WRITE_FIXED(device ← pool)`, the bytes also in hand). Hold is gated on W1 eligibility (holding ineligible shapes measured 0.45×). Bridges are deadline-bounded (30 s, AsyncCancel, must-stay-0 cancels). **Zero-copy per open file:** mainline grants it by `FOPEN_IO_URING_ZERO_COPY` on the OPEN/CREATE reply, which a zero-message open never carries — so a `MainlinePool` zero-copy session SERVES regular-file opens (the control open arm, `SQUEEZEFS_FUSE_ZC_OPEN=1`) and marks every reply; `=0` keeps zero-message opens and marks CREATE alone; the upstream RFC `scripts/kernel/upstream/fuse-zc-no-open/` asks for a connection-wide default so both hold at once.

**Teardown:** drains RELEASE every retained slot (`RELEASE_PAYLOAD`, verdicts reaped) and synthesize errors for every owed slot — both BEFORE the unmount, while the connection is live (a retained ent the kernel reclaims at its own teardown pins the exiting process); workers join; fd closed. Only an exit with no teardown (SIGKILL, SIGABRT) or an external `umount(8)` (no DESTROY on a type-`fuse` mount) leaves the kernel's drain as the recourse. Must-stay-0: `transport_requests_abandoned`, `transport_cq_overflows`, `read_dest_overruns`, `open_count_stranded` (a final FORGET with open handles counted = a lost RELEASE; under zero-message opens only OPENDIR counts — a lost RELEASEDIR), `transport_replies_oversize`, bridge cancels.

Also ship: an external **mount supervisor** (`--daemon --supervise`: stat a control inode every 5 s; after 30 s dump task stacks, SIGABRT→SIGKILL, then write `/sys/fs/fuse/connections/<minor>/abort` if `waiting > 0`; amended 2026-10-24, the owner's rulings, decision 0003 §BR: it is the mount's CUSTODIAN — it holds the journal tails (§5.2) and the write cache's ring (§6.1) across the daemon's death, replays the tails, holds one the device refused until it lands, hands the ring to the member's next mount, and exits only once it holds nothing; a process census, `squeezefs umount`'s, never reads it as the daemon — and a mount without one runs no write cache); a deadline **watchdog** that logs overdue ops loudly (per-op timeout wrappers are BANNED — dropping a handler mid-commit is the ring-wedge vector); per-class kernel TTL mount options (attr/entry/dir-entry/negative, default 1 s; an ISOLATED mount — no peer writer, no interception host — derives every class it was not given to `T_owner`, because every change its kernel did not make is invalidated by name or object before its ack: decision 0003 §AB.2).

**Access time (amended 2026-10-23, the owner's rule "never adjudicate unless certain it is not a defect"; `docs/evidence/rung-10-atime.md`; decision 0002 row 555):** the mount's atime posture is the KERNEL MOUNT's — `relatime` (the kernel's default), `strictatime`, `noatime`, `nodiratime`, `ro` — and the daemon applies it, because on FUSE the kernel decides whether a read should move atime (`fs/inode.c` `touch_atime` → `atime_needs_update` over the vfsmount's `MNT_*` flags and the relatime rule) but never tells the daemon: `FUSE_READ` carries no flag, `fuse_flush_times` writes back `FATTR_MTIME | FATTR_CTIME` alone, every read-class request ends in `fuse_invalidate_atime`, and the next `GETATTR`'s reply overwrites the kernel's in-core atime with the daemon's. So: the daemon reads the per-mount options of its own entry in `/proc/self/mountinfo` at mount and again at every change of the mount table (a `POLL_ADD(POLLPRI)` on an open fd of mountinfo, woken by `touch_mnt_namespace` — which `-o remount,strictatime` is; the kernel sends a FUSE daemon nothing else on a flag remount); `SQUEEZEFS_ATIME` (`auto|relatime|strictatime|noatime`) overrides the posture word alone. On READ (a regular file), READDIR/READDIRPLUS (a directory, unless `nodiratime`) and READLINK — every leg: the handler's, the warm ladder's inline serve, the direct device leg, the interception host's ring fast path and its direct arm's lease grant — the rule is `atime_needs_update` restated (`fuse/atime.zig`): never on a read-only mount, never under `noatime`, under `relatime` only when mtime ≥ atime, ctime ≥ atime or the atime is a day old (whole seconds), always under `strictatime`, never when the stamp equals the one standing. A due stamp is a PARKED refinement of the inode (§5.2's ack posture: RAM at once, fold-visible to the GETATTR the kernel asks next, journaled by the times drain as a `Δatime` at the flush cadence, by fsync/fsyncdir and the dismount) — never a ctime change, never a barrier, never a journal entry per read; a read that is not due costs one byte load and three compares over the record already in hand; a path that holds no record (the ring fast path) parks a relatime CANDIDATE the fold and the drain judge against the record by the same rule, one per drain tick per file. A foreign-slot inode's stamp parks the same way and the drain ships it to the holder (`SETATTR_ATIME_TOUCH`, §5.5's record-level ship): a `Δatime` iff it advances, no ctime. `lazytime` changes nothing (the daemon's apply is lazy by construction). What the daemon cannot see it cannot stamp: a read the kernel serves from its own page cache reaches no daemon, and the kernel's in-core update for it dies at the next GETATTR — so under `strictatime` a regular file's open carries no `FOPEN_KEEP_CACHE` (the open drops the cached pages: every open-read cycle reads through the daemon and is stamped, as ext4 stamps it; the posture's own cost, as its journal write per read is ext4's), while `relatime` keeps the cache (its rule makes the first read after a change a daemon read whenever the write left no whole page behind — a partial-page write marks no folio uptodate). The gap that stays is the kernel's: repeated reads on ONE open descriptor under `strictatime`, and a `relatime` first read after a whole-page write while its pages stay cached (a `fuse_flush_times` carrying `FATTR_ATIME` would close both; an owner-call for the series). xfstests generic/003 and 192 pass.

**Inode flags (amended 2026-10-23, owner ruling "build it"; `docs/evidence/rung-10-inode-flags.md`):** `FS_IOC_GETFLAGS`/`FS_IOC_SETFLAGS` and `FS_IOC_FSGETXATTR`/`FS_IOC_FSSETXATTR` are served through `FUSE_IOCTL` (linux ≥ 5.13 routes all four through the VFS `fileattr` ops; `fuse_fileattr_get/set` → `fuse_priv_ioctl`: one request per call under a private open, the argument exactly 4 B or 28 B each way, the reply exactly `out_size` bytes; `vfs_fileattr_set` reads the old state through `FSGETXATTR` first, so both pairs are served and agree). `FS_IMMUTABLE_FL` and `FS_APPEND_FL` are the inode record's (§5.1 `flags` bits 1 and 2 beside STRIPE): durable, remount-stable, one Put + ctime under the inode's exclusive guard, a foreign-slot inode's a shipped setattr verb (§5.5); every other bit (SYNC, NOATIME, NODUMP, DAX, PROJINHERIT, the project id, the extent-size hints) is EOPNOTSUPP. The kernel checks `CAP_LINUX_IMMUTABLE` and ownership before the request reaches the daemon, but sets no `S_IMMUTABLE`/`S_APPEND` on a FUSE inode — so the daemon is the ONE enforcer, restating the kernel's own laws: IMMUTABLE refuses EPERM every write, setattr (`may_setattr`: mode, owner, size, every time change — the `utimes(NULL)` touch included), setxattr/removexattr (`may_write_xattr`), unlink/rename/link of it (`may_delete`, `vfs_link`), fallocate, and — as a directory — every entry made or removed inside it (`may_create`, `may_delete`); APPEND-only admits an `O_APPEND` write at its claimed EOF alone (the WRITE carries the file's open flags; `may_open`'s law restated at the write under zero-message opens, at the OPEN where opens are served), the `*_NOW` time touch and a ctime echo, and space preallocation (`vfs_fallocate`), and refuses the rest; an append-only directory takes entries and gives none up. The two write arms that read no record — the Shared class and the staged fast path — are never reached by a restricted inode: the data plane's read view carries the record's flags under the ino witness, the admission probe declines and the staged-point cache is not filled. A flag set recalls the inode's direct WRITE leases (§7, decision 0003 §AY) and the lease screen refuses one on a restricted inode.

**FIEMAP (owner ruling 2026-10-24, "a"): not served.** The kernel answers `FS_IOC_FIEMAP` for a FUSE file itself: `do_vfs_ioctl` (`fs/ioctl.c`) catches it before the file's ioctl op, and `ioctl_fiemap` answers EOPNOTSUPP because FUSE registers no `->fiemap` (mainline 7.3, fuse-next, the 7.2 series alike) — no request reaches the daemon, so no daemon change can serve it. Serving it takes a FUSE kernel patch (`->fiemap` behind an INIT flag, drafted and proven in a VM on the unmerged branch `feat/fiemap`, `docs/evidence/rung-10-fiemap.md` there); the owner carries no kernel patch, so FIEMAP is unsupported and xfstests' FIEMAP-gated tests are `_notrun` by the suite's own probe. Were it served, the allocation unit (the 4 MiB stripe block) would also have to be reported honestly: a punch inside a block leaves it mapped with zeros where a 4 KiB-grain filesystem reports a hole.

## 5. The metadata plane

### 5.1 MetaLV: the CoW typed-KV format (the only format)

Per metadata volume: **superblock** (sector 0; magic, version, node_size default 256 KiB (64 KiB–1 MiB format knob), `features_incompat` u64, `features_ro`, extent refs to the root ledger / journal / alloc bitmap / heap, uuid, random `hash_seed`, sqzhash128 (low 64 bits) checksum with the field zeroed; a DUR-5 backup copy) → **root ledger** (32 round-robin 4 KiB slots, newest-valid-wins, record `{seq, per-tree roots (tree_id, addr, node_seq), journal_tail_seq, next_ino, bitmap_generation, membership stamp}`; checkpoint seq N writes slot `N % 32` — the ledger is DENSE: every checkpoint-class durable step outside a cycle restates the record its consumed seq names) → **journal ring** (fixed extent, `clamp(volume/64, 8 MiB, 32 MiB)`, `--meta-journal-mb` override; 4 KiB pages with a checksummed 24 B header `{magic, lap, first_entry_off, pad, csum}`; entry `{seq, len, csum(payload), records}`, max 128 KiB, multi-page continuation; one transaction = one entry = the atomicity unit) → **allocator bitmap** (1 bit per 256 KiB heap extent, A/B page pairs `{generation, csum, bits}`) → **node heap** (256 KiB extents).

**Node** = header page `{magic, addr, node_seq, tree_id, level, min_key, max_key, version, csum}` + sorted **bsets** appended at 4 KiB granularity `{magic, node_seq_at_write, journal_seq_horizon, n_records, len, csum, records}`. A rewrite (compaction/split/merge) goes to a FRESH extent, never in place; the parent pointer update is a journaled record; the old extent enters pending-free. An append writes only never-written tail bytes, so a torn append damages nothing live. Interior values = `(child_addr, child_node_seq)`; a seq mismatch at read = a concurrent SMO ⇒ reload the parent snapshot and retry (bounded). Fanout ≈ 7,000 at 256 KiB ⇒ 100 M records at depth ≤ 3 with < 3 MiB of interior nodes, always pinned.

**Keys** (big-endian, memcmp-ordered; the kind byte IS the historical tree id): inode `ino ‖ 01` → packed inode `{mode, uid, gid, nlink, flags, size, atime, mtime, ctime (i64 ns), flags2}` ≈ 96 B; dentry `parent ‖ 02 ‖ hash54 ‖ coll_seq` → `{child_ino, type, name}` with `hash54 = low64(sqzhash128(name, Key(hash_seed))) >> 10` (amended 2026-10-11, decision 0003 §M: the volume's `hash_seed` zero-extended to the hash's 128-bit secret and expanded ONCE per mount; keyed so names cannot be chosen to collide; readdir cookie = `3 + (hash54 << 8 | coll)`; `coll` probes 0..=255, overflow is a counted clean error); xattr `ino ‖ 03 ‖ hash56 ‖ coll` → `{name, value ≤ min(64 KiB, node_size/4)}` (`layout`, `system.symlink`, `system.squeezefs.parent` — a DIRECTORY's logical parent as a u64 LE, the export operations' `..` (§4, amended 2026-10-23) —, control records on ino 1); block refs `06 ‖ vol_tag ‖ block_idx ‖ owner_ino ‖ block_index` → `{version, flags(bit0 indirect blob, bit1 SHARED), reserved}`; block map `owner ‖ 07 ‖ block_index` → POINT/RUN/STRING/POINT2/RUN2 values; tree 0 control `TREE_CONTROL = 8`; shared index kind 9 reserved. Interior records of a slot tree carry kind 0 with level ≥ 1 and are journaled under `slot u32 ‖ separator`.

**Record kinds and ONE fold algebra** (shared byte-identically by point lookup, bset n-way merge, compaction, replay — test it once, property-based): `Put(value)`, `Delta(field_mask, fields)` (the Δtime record), `Delete`. Lookup: scan newest-seq-first collecting Deltas until the first Put/Delete; Delete ⇒ absent; Put ⇒ apply Deltas ascending; a Delta with no base folds to absent (counted). Compaction: one folded Put or nothing per key; **tombstone elision only if `seq < durable tail`**. Per-key last-writer-wins by record seq.

**Checksums everywhere** (sqzhash128's low 64 bits under the fixed public FORMAT KEY — amended 2026-10-11, decision 0003 §M, 0002 row 480; the owner's keyed AES-round hash, `src/core/sqzhash.zig` the pinned definition, SMHasher3-clean as 128 bits and on the low 64 alone, measured faster than xxh3-64 on every format shape; metadata format **v5**, a v4 image refuses loud naming the reformat): superblock, ledger, page headers, entries, node headers, bsets, bitmap pages. Verified once at load/replay, never per read (RAM-authoritative).

**Device posture: `O_DIRECT` on every metadata device from the first byte on every host** (shared-LUN coherence — two kernels on one nvme-tcp LUN are two page caches of one truth; a buffered read returned a stale appender page). Grain derived (`statx DIOALIGN` → sysfs `logical_block_size` → 4096). Every unit is 4 KiB-granular except the journal ring, which gets the **sector-pad law**: every reservation ends aligned behind an explicit PAD entry (checksummed, `seq == position`, entry kind PAD, skipped as a chain link by replay); admission claims `PAD_MIN + grain` slack and returns the unused part; a window's ops coalesce into one aligned run per contiguous span. A misaligned product write is REFUSED (`meta_io_unaligned_refusals` must-stay-0); a misaligned buffer is bounced (`meta_io_bounce_bytes`); a narrow read is widened and sliced. The one fallback: `EINVAL` from a trial O_DIRECT open on a REGULAR FILE ⇒ buffered, loud, `meta_io_buffered_fallback` (must-stay-0 on block devices).

### 5.2 Commit pipeline: the conveyor, the durability lane, the journal lane

Operations stage records in a task-local transaction (read-your-own-writes overlay over the node cache). **The commit conveyor**: all user commits on a volume enqueue `{staged records, shared 4a guard set, completion channel}`; a detached, panic-guarded per-volume **pass task** drains a batch (caps `max(64, cpus × 2)` txs / `max(256 KiB, ring/16)` bytes, clamped to admissible ring capacity; no timers — amended 2026-10-11, decision 0003 §L: a PAD-MAJORITY batch with a window ON THE DEVICE waits for its landing before it issues, a park bounded by the round trip's RFC 6298 predictor and gated on the measured gain against the batch's own pad (`c ≥ n/3`), so pad-majority windows are at most one per device round trip and a lone committer never waits; a batch drained while the applier venue is full waits for a window to leave it — amended 2026-10-20, decision 0003 §AW) and runs: ONE ring admission for Σ sizes (BEFORE any node lock — a parked committer holds no node lock; a checkpoint-task reserve `max(256 KiB, ring/64)` is admissible only by the SMO/checkpoint task) → ONE contiguous reservation with per-tx seqs stamped back-to-back (one `fetch_add` on a packed (lap, logical offset) word over a logical byte space that skips page headers; a CAS loop on a padded ring; the registry's open entry holds the checkpoint tail back until the lane completes it, after the apply and the landing) → the window to an **applier** (a fiber per window on a fixed set of handler lanes, `clamp(cpus/8, 2, 4)` wide — amended 2026-10-20, decision 0003 §AW: the apply was 55 % of the one serial thread), which runs: lock the UNION of leaves (ascending address, deduped, revalidate-then-retry; any member moved ⇒ drop all, re-resolve all; the seqs are the window's) → apply in queue order with per-tx seq-conditional undo → unlock → SUBMIT the batch's entries as ordinary checksummed entries (no mega-entry) → hand the window to the **durability lane**, which awaits writes in handoff order, runs the completed-prefix wait (a window reserved earlier and submitted later is folded into the group at its journal position), the hole checkpoints, ONE barrier, and fans out acks in journal order. The heap admission is the committer's before it enqueues (a refusal reserves nothing). Guards drop at the terminal outcome BEFORE the ack. Each queue entry co-owns its tx's guards until terminal outcome (a dropped committer can never strand records without isolation). Group enqueue pushes a set under one queue lock; a group's guards are ONE canonical multi-key acquisition.

**The apply (amended 2026-10-21, decision 0003 §BC):** the pass drains, recalls, admits, reserves ONE window and stamps its seqs, then hands every member its TURN; the committer applies its OWN transaction on its thread (its leaves alone, ascending, revalidate-and-retry), encodes its entry, copies it into the journal tail and answers itself; the last member of a window hands the window's image to the lane. A rolled-out member is a PAD entry over its range (no hole). `SQUEEZEFS_META_APPLY=self` is the lever (measured: decision 0003 §BC.1); `venue`, §AW's applier venue, ships; a group commit's members take the venue in both arms. **The ack point (amended 2026-10-20, the owner's ruling, decision 0003 §BB — the Lustre/ext4 posture):** under the coalesced cadence a member of a window whose EVERY member is this mount's kernel's own op (`kernel_origin`: a FUSE request) is acked once the window's RAM apply is published, its encoded image is copied into the volume's **journal tail** (a kernel-held memfd mirror of the ring the mount's supervisor holds an fd to) and the window is handed to the lane; the landing and the barrier follow on the flush cadence (`SQUEEZEFS_META_FLUSH_INTERVAL_MS`, 50 ms derived). A wire-served step, a control record (a lease, a grant, the claim, a membership page), a job's or a tool's commit is acked at the landing as before: every word of the symmetric protocol (§5.5) means DURABLE, so a peer never holds a lease or an attested step its holder's device lacks. Strict mode (`= 0`) keeps the ack after the landing and the barrier for every window. Acks follow the apply order (two windows apply in either order, §AW.4); the registry's open entry still holds the checkpoint tail back until the lane completes the window after its landing, so no ledger ever names an entry the device lacks. `fsync` / `fsyncdir` / `syncfs` barrier the lane, and a barrier an fsync pulls STARTS only once every window handed to the lane before the request has landed — the caller's acked ops are on stable storage at its return. **The crash matrix:** a DAEMON crash (`kill -9`, a panic, the supervisor's own ladder) is lossless — the supervisor replays the tail's un-landed windows to the device in seq order (the lane's own bytes: the journal's codec and CRCs; a landed window is byte-identical and skipped by seq), barriers, and only then releases the writer claim (the guard's open file description is the supervisor's too, so the flock outlives the daemon; a successor's `flock` waits out the replay; a PR registration outlives the daemon until a peer's ladder preempts it at `T_owner`, far past any replay). **A replay the device refuses is HELD, never discarded** (amended 2026-10-24, the owner's ruling, decision 0003 §BR): before it releases the writer claim the supervisor copies the tail's written slots into a held copy in the host's RAM runtime directory (`/run/squeezefs/journal-tails/<volume uuid>.jtail` — a tmpfs, so the copy outlives the supervisor, its SIGKILL included, and dies with the host, whose power cut is the window below); the copy names its volume and set and each window's reservation position, so a foreign copy is refused and a STALE one — the ledger's checkpoint tail past every window it holds: a writer ran without it — is removed unwritten (a window behind that tail is skipped); the replay is JUDGED against the device's own journal — the prefix law: the held windows are overlaid in seq order and kept only while the journal's replay scan confirms no drop the device did not already have, so a window that lies past a hole the copy does not hold (a window acked at its landing whose write failed and was rolled back) is never written, counted and logged as lost, since a transaction applied past a missing one is a state no writer had; the supervisor retries the replay every tick under a NON-BLOCKING writer lock (the device's superblock read for the volume's identity first) and removes the copy once it lands and barriers; the volume's next writer, under its own lock and before it reads its ring, replays what is left, and refuses to open while the device refuses it (removing the copy by hand mounts without it and loses that metadata). So acked metadata survives a metadata device that fails mid-flush and recovers, whoever comes first — the supervisor's retry or the next mount — and a copy is released only after a replay landed. A JOINED ring's refused replay is not held yet (its ring may be re-leased by the manager's ladder; owed). A mount with no supervisor (foreground, `--daemon` alone) or whose supervisor is itself gone before the replay has no replay: the next mount finds only the device, and the power-cut window applies. A POWER CUT loses at most the flush window of un-fsync'd metadata — acked-but-unflushed creates may be gone, fsync'd ones never; whole-transaction atomicity and the torn-write immunity stand (the replay's checksum walk). A journal write that fails AFTER an ack rolls nothing back (RAM is what was acked): the volume latches FAILED at once — EIO until remount, ext4's journal abort — and the tail's replay retries the bytes at the daemon's death. **The pass and the durability lane run on ONE OS thread per writable volume (`sqz-jrnl<N>`) that owns the volume's journal io_uring and parks IN it** — a task wake and a device CQE are one `io_uring_enter` wait (the cross-thread wake hop measured 59–62 % of the journal write's round trip); the appliers run beside it.

**Failure:** a journal write error re-acquires leaf locks and rolls back per-record seq-conditionally (a newer committed record stands); the reserved range stays unwritten (replay's checksum walk drops it). Repeated failures latch the volume FAILED. Nothing inside the replay window `[tail, head]` ever fails a mount loud — a tear there is a legitimate power-loss artifact: drop the entry, resync at the next verified page header with `first_entry_off ≠ 0xFFFF`, count it (`replay_dropped_torn > 0` after a CLEAN unmount is the corruption alert).

**Journal economy:** rename = one whole-tx entry (dentry surgery + both parents' Δtimes + moved inode Δctime); the kernel's SETATTR ctime/mtime echo is absorbed when it matches committed/in-flight times (never blanket suppression); unlink destroys ride batched `destroy_inodes` (≈ 1.0 entries/op; gate ≤ 1.05); a size-neutral write's `mtime`/`ctime` is a PARKED refinement under the coalesced cadence (fold-visible on every inode read, journaled by the batched times drain on the flush cadence / fsync / dismount, ≤ 16 inos per entry; an extending write commits its size claim per op; strict mode commits per write — amended 2026-10-12, decision 0003 §L.6). Parent-time updates are Δtime merge records under the SHARED parent guard; under the coalesced cadence a regular child's create, symlink or unlink PARKS the parent's stamp instead (the same refinement, the same drain, the same `fsyncdir`/dismount points; the Δ was the one record of every create that landed on a leaf shared by every child of the directory — amended 2026-10-20, decision 0003 §AV), a directory child's nlink shift stays the exclusive `Put`, strict mode stages the Δ. Hot fold reads serve from a per-key materialized folded head in the dirty delta + a bounded 8-entry memo on the immutable snapshot (property test: memo ≡ from-scratch fold).

### 5.3 Checkpoints, writeback, SMOs, space

- **Node cache**: RAM-authoritative; `CachedNode` = arc-swapped immutable snapshot (merged sorted view + on-disk bset list; readers latch-free, binary search, slice views) + a dirty delta under the node write lock. Demand paging loads one node per miss, single-flight per address; torn-bset classification is positional (truncate at the first checksum failure; a later valid bset with `journal_seq_horizon ≤ durable tail` fails the node loud — covered data was barriered; otherwise drop silently and count). Clock eviction; dirty nodes pinned; interior and ledger pinned. Budget `SQUEEZEFS_META_NODE_CACHE_MB/PCT`, default `max(budget/16, 512 MiB)` per volume.
- **Writeback**: freeze the dirty delta under the lock into a 4 KiB-padded bset image, release, append outside the lock. Each node tracks `oldest_dirty_seq`.
- **Checkpoint** (≤ 1 s cadence `CHECKPOINT_MAX_AGE_MS`, or journal distance > ring/2, or dirty nodes > `max(4096, budget/32 ÷ node_size)`): flush the chosen dirty set → barrier → `tail = min(oldest_dirty_seq over nodes still dirty, else head)` **rounded DOWN to entry starts** → write the next ledger slot. Ring reclamation gates on the ledger record being DURABLE (`reusable_upto` watermark, post-barrier) — the head bounds against it, never the logical tail. A committer parked at ring admission kicks the checkpoint task with a park mark that makes a cycle due with an immediate barrier.
- **SMOs** (compact, split, merge, root grow/collapse) run on the per-volume checkpoint/SMO task, one at a time: build successors from a frozen snapshot (no locks) → barrier the images → parent-then-child locks → re-freeze the build-window delta into the successor → swap the cache mapping (old marked superseded, snapshot kept for in-flight readers) → RESERVE the interior-pointer + alloc/free records inside the lock window (from the reserve) → release → write the entry. Pointer records: `Put(R.max → succ)` + `Delete(L.max)` for a merge; splits analogous. Root swaps journal no pointer record (the next ledger names the root) and pin a **dying floor** at the entry start. **Replay is two-phase**: phase 1 interior records `(level DESC, seq)`, phase 2 content by key through the final routing. Writers resolve → lock → revalidate → retry (`commit_smo_retries`).
- **Leaf merge**: `C` = fold capacity; mergeable iff `f(L)+f(R) ≤ ¾C ∧ min ≤ ¼C` (the split's constants read backwards; hysteresis structural). Triggers: the flush pass's O(1) prefilter, the heap-full sweep (bounded per cycle to one tick period, cursor-resumed, levels walked leaves-up), the D4 defrag arm. Interior recursion + root collapse are the only way height decreases.
- **Space**: extent allocator = bitmap with a lock-free RAM mirror (`fetch_or` claim) + journaled deltas; **pending-free gated on checkpoint COVERAGE of the freeing record's seq** (never mere ledger durability) so any ledger slot a mount may select references only never-overwritten extents. Compaction reserve `max(8 extents, 2 %)`; a user commit PROMISES its projected SMO extents at admission (`heap_promised`) and refuses growth `ENOSPC` while compactions/deletes are admitted down to the compaction floor `reserve/2`; a cycle that defers a node for NoSpace is the counted non-terminal space class; the FAILED terminal is the wedge class alone (parked retirements with no release and no tail advance for 8 barriered cycles). Pending-free cap is a pressure valve, never a liveness gate (the flush pass's own compactions retire forced into an unbounded overflow).
- **Inodes**: monotonic `next_ino` watermark, never reused, recovered as `max(ledger, replayed window max) + 1`; ino 1 = root.
- **fsync**: the trailing coalesced barrier covers journal pages; a barrier an fsync pulls starts only after every window handed to the lane before it has landed (the ack precedes the landing under the coalesced cadence — §5.2 "The ack point"); strict mode (`META_FLUSH_INTERVAL_MS=0`) barriers per commit, coalesced.

### 5.4 Routing: the derived virtual width, round-robin volumes, online slot migration

- `W = 2^16 = 65,536` routing slots per set, DERIVED (the u16 slot-id wire type), frozen forever (W is baked into every global ino: `slot = (ino−2) % W`, `local = (ino−2)/W + 2`, inverse `ino = (local−2)·W + slot + 2`; ino 1 → slot 0, the root pin). "Dynamic" = the slot→volume map is the only thing that moves, and it is online-migratable.
- A fresh set parks slots as one arithmetic-progression run per volume (stamped as stride runs `(start, stride, count)` in the ledger membership stamp — incompat bit; budget caps on runs/cursors). Guest slots carry their own keyspace: `guest_local_ino(slot, local) = (slot+1) << 40 | local`; native keyspace `[0, 2^40)`.
- **Mint spread**: directories' children mint round-robin over the healthy volumes (`pick_mint_volume`), and within a volume over `MINT_SPREAD = 64` rotor slots, so a volume's load is divisible into ≥ 64 movable slices from birth. (Amended 2026-10-13, decision 0003 §AA.1: a child of a directory this mount leases outside the native slot stays on its directory's member — §5.5's affinity ranks first, since a child on another member makes every create, unlink and rename of it a cross-owner intent with two device barriers; the round-robin spreads the root's children, so a set spreads by subtree.)
- **Online `migrate-meta-slot`**: bulk copy from read snapshots → delta tee in the conveyor pass (keys only, bounded, overflow ⇒ fresh snapshot) → per-slot cutover gate checked at op entry BEFORE any lock (parked ops hold nothing) → target-first ordered flip (B stamps `E,+s`; A stamps `E,−s`; config mirror); crash resolves by per-slot highest-epoch-wins. `add-meta`/`remove-meta` are offline; set changes drain staging then rebind the generation stamp.
- Health-weighted placement for directories by estimated remaining capacity; order-independent mount discovery via per-volume membership stamps with URI-disagreement refusals.

### 5.5 Symmetric metadata: every mount an equal authority (the default format)

**Incompat bit 17 = the forest + appender directory, stamped by a plain `format`.** `--single-writer` is the one flat opt-out (D0 one-writer guard, §5.7). `SQUEEZEFS_SYMMETRIC_META` defaults 1; `=0` on a stamped volume refuses the writable open ("once armed, stays armed").

**The forest (KD-SYM-2):** one mixed-kind KV tree per routing slot. A slot IS a contiguous key range; a record's slot is `key_ino >> 40` (refs by their owner ino). Tree 0 (`TREE_CONTROL`) is the manager's: `slot_state:{s} → Unleased{root, cursor, g, seq_floor} | Leased{appender_id, g, page_addr, root, cursor, slot_tree_extents}`, `slot_tails:{s} → {g, tails}` (inline ≤ the value cap, spilled to extents above), `extent_grant:{a}:{chunk}` (the grant record as a family of stamped 4 KiB chunks; a change rewrites only the chunks it touches, staged behind a move marker when it outgrows its entry), `appender_alloc`, `appender_hint:{identity}`, `node_seq_incarnations`; on VOLUME 0 only the set-wide records `alloc_lease:{vol}`, `dead_member:{id}`, `recovered:{id, vol}`, `dir_rename`, `custody_quarantine:{slot}`. Slot trees are minted lazily (an empty slot owns no extent). The §4.10 digest walk runs over `(kind, legacy key, value)` so a forest and a flat volume with the same records digest EQUAL.

**Partition law:** a slot tree has exactly one writer-cacher, its lessee; `apply_locked` refuses a mutation to a slot this mount does not lease (`meta_kv_leaf_lease_refusals` must-stay-0). No boundary splits, no leaf sharing, no cross-node cache coherence.

**Appenders:** every writer has a 4 KiB A/B **appender page** (magic, id, generation, csum; identity `{node_token, mount_slot, writer_id}`; term; state `{Free, Live, Recovering, Recovered}`; `is_manager`, `home_volume`; ring segment table ≤ 8; `head_hint`, `ledger_tail_seq`, `ckpt_seq`, `seq_offset`; extent grant ≤ 4 runs (the page names the largest 4; the RAM pool holds the rest); leased slot entries `(slot, state, g, slot_tree_extents, root, cursor)` ≤ `SLOT_PAGE_BUDGET` = 108 at the fixed part's natural widths; a layout version byte). Pages are read newest-valid-wins over FOUR slots (directory pair + two ring-side) under the **directory-first law** (a page naming a ring table the directory does not yet name is written to every such directory slot in the same barriered step). Appender 0 = the format-time fixed ring (its 4 page slots are the ring's first 4 pages); appenders ≥ 1 live in the **appender directory** (an extent chain named by the superblock). Capacity = `heap/16 ÷ ring` (published; a join past it refuses naming the volume count as the lever). Ring size `clamp(2 × ewma_commit_bytes/s × CHECKPOINT_MAX_AGE, 512 KiB, volume/64)`; growth = replace-when-drained (`GrowRing`, one doubling step); a rejoin starts at tree 0's `appender_hint`. Every carved ring extent is ZEROED before a page names it; a fresh incarnation's seq space continues from `max(page.head_hint, ring 0 head)`.

**The record-seq space is monotone across rings:** every ring stamps `position + seq_offset`; a release records the departing ring's frontier as the slot's `seq_floor`; a grant raises the receiving ring's offset above it. **Node seqs are incarnation-scoped**: base `B` from the volume uuid; incarnation `o ≥ 1` minted at every join; a joiner mints in `[B + o·2^38, B + (o+1)·2^38)` (2^25 incarnations); every cross-appender comparison is equality or generation, never order.

**The manager lease** (per volume; the D0 ladder winner; an ordinary appender with `is_manager`; KD-SYM-2: it leases the native slot, which holds control records and `/`'s dentries; volume 0's manager is the set-wide role holder): writes tree 0 and the fixed ledger, arbitrates slot leases, allocates appender pages, grants/returns extents, maintains UNLEASED slot trees. **Zero per-op work.** Verbs (one wire family over the cluster wire): `JoinAppender`, `LeaveAppender`, `AcquireSlots/AcquireSlot`, `OfferSlot`, `ReleaseSlot`, `ResolveSlot`, `ExtentGrant`, `ReturnExtents`, `GrowRing`, `PublishRoots`, `PublishEndpoint`, `ResolveEndpoint`, `DirRenameLock/Unlock`, `MarkShared/ShareBlock/ReleaseShared`, `BlockGrant/ReturnBlocks`, `AllocLeaseAcquire/Bitmap/Release`, `RecordDeath/RecordRecovered`. **Every verb is idempotent against DURABLE state** (a `Live` page ⇒ `Joined{already}`, etc.), never a RAM dedup window; **every wire word is SCREENED against durable/derived state before any effect** ("bounded codec = bounded execution": a bad `seq_floor` near u64::MAX, a bogus root, an over-wide run → `STATUS_REJECTED`, nothing written); retryable classes are TYPED (`Deferred`, `SlotMoved`, `StaleHolderView`, `HolderUnreachable`, `MembershipPending`, `ListenerRefused`, `StaleOwnerEra`) and surface as EAGAIN, never EIO/EINVAL. Control entries admit in the USER class (a verb storm never eats the checkpoint reserve); a wire verb whose ring-0 control entry finds the window full answers `Deferred` and kicks the checkpoint.

**Extent grants:** `grant = clamp(2 × ewma_smo_rate × failover_bound_s, 8, free_heap/(4 × appenders))`, refilled at 50 %; a WIRE joiner measures its own SMO rate and names its size; the grant is a POOL (retired images recycle; surplus returns at a quiet cadence). An appender out of grant with the manager unreachable defers compactions and refuses `GrantExhausted` (EAGAIN-class), never ENOSPC. Closure: `extent_grant_extents ≡ claimed + returned + unclaimed`.

**Slot acquisition and minting (first-writer-takes-it, load-bounded parent affinity):** at join a node leases `M = clamp(W / (2 × writers_known), 1, 64)` rotor slots. A child mints into its parent's slot iff this node leases it, it is not a native slot, and the parent's tree is below the soft **affinity ceiling** `A_max(t) = max(used_leaf_bytes(volume)/64, node_size)`; else into the rotor slot with the most headroom (over-cap rotors may request up to `2M`). `setfattr -n user.squeezefs.gather -v 1 <dir>` forces children into the directory's slot (read-mostly directories). Cursors travel with the lease as FLOORS: `cursor = max(tree-0, page, in-window max minted, high live key) + 1` — never re-mint.

**Handover (holder-decided, ONE requester, never thrashing):** a live holder is never recalled against its will; foreign writes ship to it (the metanode arm). The holder OFFERS slot `s` to requester `q` iff over one common window `T_idle = T_owner`: `ops_q ≥ 2 × ops_h ∧ ops_q ≥ N_floor`, `N_floor = max(2, ceil(ewma_handover_ns / ewma_ship_ns))` (cold start: `4 × ewma_barrier + 3 × ewma_ship_rtt`). `ops_h` counts the holder's namespace ops on the slot's SUBTREE (walk the directory-parent memo to the root; ancestors on other volumes credited there). The idle arm is the same rule at `ops_h = 0`. Aggregate shipping by a crowd never triggers; a ship into a striping domain feeds no window. **Flush-then-transfer:** gate `Releasing` → drain the slot's door tokens → cycle until the region's `reusable_upto` passes the slot's record frontier and the root is published (bounded `COVER_CYCLES_MAX` = 64, `Deferred` on a moving tail) → page `Releasing{root, cursor, g}` + barrier → `ReleaseSlot{root, cursor, tails, seq_floor}` → tree 0 `Unleased` → page drops the slot. **Two durable homes at every instant — never zero.** The **commit door**: every commit takes a token per slot before queueing (held to terminal outcome); `Releasing` parks, a foreign lease refuses `SlotBusy` (EAGAIN, "ship to the holder"), unleased acquires first-touch with a parking admission. The **structural door**: a grant to any appender but the manager takes the SMO mutex first and cycles ring 0's window clear of the granted slots. **Page-budget overflow law**: a region holding more slots than its page names publishes the overflow roots into tree 0; a publication remembers its HOME (`Tree0 | Page`); the ONE page writer ranks entries by what a slot loses if dropped (mid-handover first, then page-homed-only, then unpublished, then tree-0-named) and publishes a page-homed slot into tree 0 BEFORE the page drops it. A slot's cursor rides page 0 BEFORE barrier #1 (a death between the ledger record and the page write must not reopen slots one cycle stale). LRU release of idle non-rotor slots past the budget; forced shrink to the derived `M`; a region is released when its last slot goes and its ring is drained.

**Slot → holder resolution:** tree 0's lessee + the appender→endpoint table (endpoints published into each writer's claim-set entry) through a per-mount `SlotHolderCache`; `ResolveSlot` is the fallback; `NotHolder{current}` redirects are followed once; a redirect to a lessee the membership owner lists DEAD is `HolderDead` (never dialled).

**Tokens — GPFS-strict, the ONLY foreign-read method:** a foreign object (inode + its carried xattrs; a directory's dentry set or stripe map, paged by cookie) is read under a token from its slot holder; the grant reply CARRIES the records (Lustre's intent lock); 0 RPCs and 0 device reads while cached; the holder's conveyor pass recalls the union of its batch's objects' tokens ONCE, under the batch's 4a guards, BEFORE ring admission, and proceeds on every ack or the reader's membership lease expiry; a recall unacked by a LIVE member past its lease TTL is `dlm_token_recall_timeouts_live` (must-stay-0). A reader acks only after its in-flight DMA reads on the ino drain (per-thread serve stamps) and its block-key census for the ino is purged; a DIRTY local layout entry is KEPT (the writer's acked bytes) and only clean entries are discarded. A grant on an object a pass has in flight PARKS to the settle (register-then-check, model-checked). The token wire has its own verb block (`Grant`, `Recall`, `RecallAck`, `Release`, `CustodyGrant`). `-o ro` mounts are member-readers + token clients (every reader TTL derives to 0; `reader_staleness_bound_ms` reads 0); with NO live writer a `-o ro` mount is the QUIESCENT reader of the checkpointed projection that fail-stops `ESTALE` at the first poll that sees a writer. Every writer is also a token client of the holders it writes to (the read divert). Readers' planes FOLLOW a holder that moved its listener (re-resolve off durable state, re-point in place). The S5 epoch-poll of the fixed ledger survives as the CONTROL plane only (predicted-slot 4 KiB read first; a 32-poll gap belt reads the whole ledger).

**Cross-owner namespace ops (POSIX across holders):** `create/mkdir` under a foreign directory, `unlink/rmdir` of its entries, `link`, `rename` across holders are ONE intent (step 0's records + the intent in the initiator's ring, barriered) whose foreign steps ship as verbs (`XvStep`, `LookupExact`, `XvGuards`/`XvRelease` — foreign 4a guards TRAVEL to the holder in ascending appender-id order) to each step's slot holder, applied by ONE applier under the holder's door, idempotent under the recorded `(pre, post)` witness, then retired. The inode WITNESS is read AT THE HOLDER (through the token divert), never off a stale projection. A create in a foreign directory mints the child in the CREATOR's rotor. A ship that fails leaves the intent OPEN (never fail-stops); a roll-forward cadence completes it; `xv_cross_owner_intents_stuck` must-stay-0; closure `minted ≡ retired + open`. A step whose slot moved mid-plan re-dispatches once (local apply takes its own guards try-only, all-or-nothing). **Every rename whose source is a directory takes the set-wide `dir_rename` lease** (volume 0's manager; the Lustre BFL) and checks ancestry on EXACT data through exact lookups at each ancestor's holder. **Record-level mutations of a foreign-slot file** (`setattr/setxattr/removexattr`, the layout publish) are each ONE shipped verb to the holder under the per-holder custody lease, served under the holder's door with the object's tokens recalled, then the holder's own caches AND kernel view invalidated (`FUSE_NOTIFY_INVAL_INODE` + `FUSE_NOTIFY_PRUNE`).

**Directory striping (DNE-2 shape, K = 64):** a hot directory `D`'s dentries spread over `K` stripe inos `D_0…D_{K−1}` (ordinary nameless dir records minted in DIFFERENT creators' slots on `D`'s volume), `stripe(name) = hash54(name) % K` over the seeded hash (one order ⇒ the K-way readdir merge is the shipped cookie order). The map = `K + 2` reserved NUL-led dentries in `D`'s own tree (`\0sqz.stripe:NN`, `\0sqz.migrating`, `\0sqz.striped` LAST = the commit marker, naming stripe 0), written as ONE intent. Triggers: automatic when foreign ships into `D` exceed `N_floor` per `T_idle` from MORE THAN ONE creator (one creator = handover candidate); explicit `setfattr -n user.squeezefs.stripes -v K`; `-o stripe_dirs` at mkdir. Names re-home LAZILY (`D`'s own tree is a permanent secondary home for reads; every mutation keys the STRIPE and re-homes first). `stat D` = the fold `nlink = D.nlink + Σ(D_i.nlink − 2)`, times = max, persisted once per checkpoint cadence. `rmdir D` = ONE intent under ONE exclusive guard set over `D` and every stripe (probe empty, `SetNlink 2→0` dying marks, markers out, destroy as hygiene). A stripe never carries a map. fsck C17 report-only.

**Data-plane planes under the symmetric model:** per DATA volume a floating **allocation lease** (`alloc_lease:{vol_tag}` in tree 0 of volume 0; first-come at term 1; a dead holder succeeded only after `dead_member:` AND `recovered:{holder, home_vol}`) owning a **data allocation bitmap** (1 bit per block, A/B pages `KVDA`, 32 KiB/TiB, in extents of the holder's grant on its HOME volume; mutations are `vol_tag`-prefixed kind-4 deltas in the holder's ring carrying the holder term, under one ordering lock, pages written before barrier #1; the C6/C8 census is the oracle, `data_alloc_bitmap_drift` must-stay-0 in the loss direction), **ranged block grants** `G = clamp(2 × ewma_blocks/s × T_renewal, 64, cap/(2 × writers))` (floor 64 = one write-pipeline BDP window; carve = lowest clear run at/above the frontier, bits SET at the carve; writer tops up at 50 % as a PULL; liveness = the death ledger, never a TTL; a dead writer's grants revoked + quarantined under a dead epoch; every live writer declares its held windows on each renewal so a successor adopts/releases a crashed incarnation's bits), terminal frees of a non-holder SHIP to the holder, the free-grace ring, reclaim, quarantine, and the **shared-block index**. **On a grant-armed allocator the bitmap IS the free list**; a holder's `df` used count is its bitmap population minus its own unconsumed window. Pack blocks are scoped per `(writer, slot, data volume)` so a block's references live in ONE slot tree and `refcount(block)` is one range probe (`block_ref_probes`); a block referenced from two slots arises only through clone/reflink → the **clone protocol**: `MarkShared` at the source's holder (SHARED bit on every source record, one tx under the 4a guard) → `ShareBlock` at the index home (the allocation holder) → publish the dest refs WITH the bit; a terminal free of a SHARED block is never decided locally; a surviving sole owner stays SHARED (the un-share protocol needs a share-in-flight witness — owed, priced as W1's CoW fallback). **Membership is sharded by home volume** (volume v's manager is the S6 owner for mounts homed on v); deaths propagate through the **death ledger** in tree 0 of volume 0 (`RecordDeath` from the home shard's eviction; every manager polls it as a projection within `poll + CHECKPOINT_MAX_AGE`). **A manager's death is its home shard's outage**: a symmetric appender's `T_self` action is **PARK-AND-RECLAIM** (acks held at a pre-admission gate, page/ring/leases kept, checkpoint task running, reclaim in the successor's grace window; `T_park_max = failover_bound + grace`; expiry = the terminal poison, `appender_park_expiries` must-stay-0).

**Death and recovery (§5.9):** home shard evicts at `T_owner` (45 s) → `RecordDeath` → each volume manager: PREEMPT-AND-ABORT the dead registrant key (PR) → page `Live → Recovering` → read the ring ≥ `ledger_tail_seq` → RAM lease table marks the dead slots `Releasing{dead}` (first touches refused, structural class the manager's) → root = newer of page/tree 0 installed writer-legal after dropping the stale slot nodes; cursor = `max(recorded, page, window max + 1)`; `seq_floor = max(recorded, dead frontier)` → two-phase replay in the structural class + data-bitmap deltas → cycle until no dirty slot-tree node → record tails (EVERY leaf on non-PR substrates — the full tail scan; skipped on PR) → tree 0 `Unleased` per slot + `slot_tails` + grant record minus the trees' images → RAM table `Unleased` LAST (an RAII rollback restores every RAM word and the slot's tree on any error; the page stays `Recovering` for the re-run) → unclaimed grant + orphan images returned → page `Recovered{ledger_tail_seq = head}` → `recovered:{id, vol}` → roll forward open intents. **A `Recovered` ring is never replayed** (the dead node's remount starts a fresh head). Bound `appender_recovery_bound_ms` derived (ring bytes ÷ 230 B per entry; ≈ 800 files/leaf × 120 µs cold load × three leaf passes; ≈ 1.3 s shipped). Closure `dead_members_acted ≡ recorded × regions held`. Open files stay usable (the open table is the mount's, never the incarnation's; every record is re-read under the successor's tokens or first touches). ### 5.7 The single-writer mount guard (the `--single-writer` class; the D0 ladder every writer still walks)

Three layers: (A) an exclusive non-blocking `flock` on a DEDICATED daemon-lifetime fd (never a cache-owned fd); (B1) NVMe Persistent Reservations where `RESCAP ≠ 0` (Write-Exclusive rtype 1 on a flat volume; a fenced holder fail-stops at its first post-fence journal barrier: a reservation-conflict errno at any barrier latches FAILED); (B2) a `writer_claim` record `{id, ts, pid, boot}` on ino 1 committed and barriered before the checkpoint task spawns and before FUSE arms, heartbeat 10 s, stale at 45 s. No bypass knob. Recovery ladder: same-host dead-pid proof → PR preempt → TTL → `squeezefs claim clear`. Under the symmetric default the D0 winner IS the manager and a later RW mount JOINS it (`JoinAppender` over the wire presenting its own `(node, mount_slot)` identity; a clean `umount` + remount at another mount point is a same-node successor of the allocation lease).

- **Packed** (GPFS-style many-files-per-block): the tenant mapping is the size-carrying decorated form `[backend://]offset[@incarnation]:rel_off:len` (`rel_off % 4096 == 0`, `rel_off + ceil(len) ≤ CHUNK`; a malformed decoration refuses `EIO` at ONE parse choke point — never resolves to another tenant's bytes). Seal triggers: FULL, DISMOUNT, DRAIN, BATCH; no idle seal. Reads: ONE ranged routed window read on the mapping's OWN backend. Compaction = the defrag D1 arm (`defrag --pack`): occupancy from the census's C8 walk, each distinct `off` group copied ONCE at max len into a pre-allocated unpublished destination, every referencer republished, destination refcount raised to the referencer count before any publish. - **Striped**: 4 MiB blocks (configurable `CHUNK_SIZE`) across the active data volumes with health- and fill-weighted placement (`health_effective = health − clamp(1000 × (fill − mean), 0, 300)`, a published immutable choice table), block map + durable refs. Writes that grow past thresholds promote layouts DURABLY (block I/O before the metadata type flip).

### 6.2 The write path

**ONE write admission (the "one path" law): always the cheapest legal I/O.** Own the payload before ACK (retain page-cache folios under payload retention; extract GUP/O_DIRECT pages at delivery; ring severs are already owned). Then, per page-aligned single-block PIECE (the write splitter makes pieces single-block; the kernel's writeback grid straddles 4 MiB boundaries once a chunk end leaves the 1 MiB grid, so judge PIECES, never the whole write):

1. **Device overlay (zero daemon copies)** iff the range has a final unpublished LBA or is a mapped striped passthrough block with `len > PATCH_MAX` (or a record is already Open on the block), no RAM/staged/extent/shadow custody, no write verification, single writer: install a reader-visible overlay record `{old_binding | Hole, dest (fresh unpublished, incarnation unstable, fsck visibility guard, mint rollback owner), completed coverage, inflight ranges with range claims + generations, state Open→Frozen→Published|Superseded|FenceDropped}` BEFORE ack → reserve the destination BEFORE DMA → `WRITE_FIXED(device fd ← slot)` on the FUSE queue ring that registered the slot → CQE ⇒ range joins coverage → at completion the record FEEDS the rewrite epoch (an overwrite's displaced key parks; a fresh block parks nothing — amended 2026-10-19, decision 0002 row 546: the save is the publish's coalescing unit for both, so a lay-down no longer journals its map per block) and the epoch's ONE save flips map + refs → free the displaced binding only after the durable publish. Reads prefer the overlay: snapshot `(g, C, dest)`, covered ranges from dest, gaps from the old binding or zeros (never the dest's uncovered recycled bytes), revalidate, else bounded retry then the serialized settle; a failed direct read that landed bytes in a caller-visible dest rewrites the whole window. fsync: FREEZE → COMPLETE → SEED GAPS (one ranged read of exactly the K uncovered bytes) → FLUSH → PUBLISH → META SYNC → deferred frees. Always a fresh destination, never in place (ACK-early + crash mid-DMA into a mapped offset would tear durable bytes). Admission rides the write-pipeline depth governor. Must-stay-0: `overlay_fence_drops`, `overlay_unpublished_at_fsync`. Measured: overwrite ingest 31.0 → 32.1 GiB/s at half the daemon CPU, merge share 1.000 → 0.001.
2. **W1 sole-owner extent patch** iff: striped file with the UNDECORATED whole-block mapping; no RAM buffer, no staged entry, no open overlay for the key; passthrough volume; `refcount == 1 ∧ !SHARED` (durably confirmed by one probe of the ino's slot tree on an armed set; a foreign-custody file declines; a non-holder joiner declines); offset and length 4 KiB-aligned, `len ≤ PATCH_MAX = block/8` (512 KiB), non-extending, within one block; not stream-adjacent (per-inode `last_write_end`). Steps: mark incarnation unstable → `fence(SeqCst)` → re-check refcount → ONE aligned DMA at `offset + rel` → publish → purge the key from all four read tiers → ACK. Zero allocation/free/map merge/journal/staging. The clone side: pin (refcount CAS) → `fence(SeqCst)` → snapshot the incarnation; unstable/moved ⇒ unpin and retry (3 attempts). Both fences are load-bearing (model-checked). `patch_edge_rmw_reads` = 0 by contract (only app-written sectors are ever rewritten). Result: 354–397 → 61–67 k IOPS on rand-4k. W1 is un-disableable on a production mount.
3. **Accumulation**: ONE merge copy from the lease into the **exclusive-owner, copy-on-write 4 MiB buffer** (pooled, 4 KiB-aligned, memset-elided: uncovered bytes are recycled pool memory and must never escape — coverage-aware reads zero-fill replies; every stage/upload exit zero-completes the complement under the block lock). Mutation requires provable uniqueness; readers get immutable snapshots; a shared buffer copies first. **Coverage union** = a primary contiguous run + rare out-of-order runs; the write-through trigger is `union == whole block` (order-blind; kernel-split out-of-order O_DIRECT segments are the normal case — `FOPEN_PARALLEL_DIRECT_WRITES` stays on; the end-offset proxy misfired at −34 %). Write-through: snapshot under the block lock + capture `write_epoch` → crypto → allocate (incarnation unstable) → aligned DMA → publish → re-lock, revalidate (entry present ∧ epoch unchanged) ⇒ ONE block-map merge under the inode meta stripe; superseded ⇒ free the fresh offset, publish nothing (**latest-wins supersession**). Inside a **rewrite epoch** (per inode): displaced A keys park, B offsets hold in-flight guards, ONE whole-tx save swaps the epoch at close (full coverage / the shadow at half the save's derived width (`write_epoch.CLOSE_WIDTH`: the record that reaches it owes the close, so a stream closes one epoch per window while the previous save is in flight) / fsync / the write-back timer within `T_wb` — under the close posture the close's FLUSH or RELEASE — / shape change / ENOSPC / idle TTI/10 / fence / unmount); parked A keys are freed only after a durable save no longer references them; a fence at close publishes nothing and frees nothing. Transformed volumes use a worst-case scratch (`block + 128 KiB`) and store-raw for incompressible blocks (frame bit 31); compression is best-effort per block.
4. **W2 extent overlay** for sub-cap patch-ineligible shapes (transformed volumes, shared blocks, holes, unaligned): a compact sorted extent list + payload slabs charged to the budget as `parked_extent_bytes`; escalation to a full buffer at ≥ 25 % coverage; spill = versioned+checksummed staging extent records (NO seed read at spill); fold at the last moment seed-once + k extents (`FOLD_MAX_EXTENTS` 64, bytes block/4; amplification ≈ `2048/k + 2`).
5. **Staging** absorbs partial tails, RAM-pressure spills, write-through failures (never-lossy). Staged flushes DMA straight from the mmap through a write-only consume-by-value guard.

**The write-back drain within `T_wb` (amended 2026-10-14, decision 0003 §AJ — the owner's ruling: "Yes: drain on a bounded timer"; it replaces the drain at close of §AF):** a file's write custody (parked blocks, W2 extents, open overlay records, its rewrite epoch) lands within `T_wb = A + τ + D` of its write — `τ` the flush cadence (50 ms derived), `A` the checkpoint's cadence ceiling (1 s), `D` the drain: with `D ≤ τ`, the 1,100 ms landing ceiling of a dirty metadata leaf — or at fsync, fdatasync, syncfs and the unmount, which drain synchronously as before. Close is no durability point (ext4's law): a FLUSH answers ENOSYS (the kernel latches `no_flush`, so every close(2) is local), a CREATE answers `FOPEN_NOFLUSH`, RELEASE drains nothing. Every write notes its ino in an age-ordered set (the birth of its oldest custody); one timer pass per `τ` lands every custody born by `now − A` — per block, so a block filled within the age writes itself through and never lands partial — and re-owes what is younger. Memory is the budget's write-custody components (a writer past the parked cap parks at the gate or lands the coldest custody itself — and the daemon answers, never holds (amended 2026-10-24, decision 0003 §BQ): a write the gate holds behind flushes the plane refuses answers before the kernel's request deadline would end the whole mount — ENOSPC when a flush inside its wait met the store or the device out of space (a thin pool's ENOSPC), else EIO — at the applied request timeout less one 15 s check period (120 s at the lattice's 135 s), and the episode answers every later held write at its first refused flush; never a byte of it recorded, the parked set left to its retries); under a load the device cannot absorb, `D ≤ C ÷ W`. A crash may lose an acknowledged write younger than `T_wb` — whole or absent, never torn, never another file's bytes; synced writes are never lost. `SQUEEZEFS_WRITEBACK_POSTURE=close` keeps §AF's drain at the close the kernel reports as the A/B control arm.

**Write admission ledger:** `admit_write_{overlay,inplace,accumulate,inline}_bytes` sum ≡ user bytes at ACK. **Shared-mode inode admission:** classify `EntireOp | MetaPrepOnly | Shared` (shared = cache-resident striped write with `end ≤ min(attr size, meta size)`; validate → probe caches without awaiting → classify → acquire → revalidate under the guard → at most ONE upgrade to exclusive); drop the inode guard before data I/O; the lock is write-preferring. Measured: a scheduler-wake convoy of ≈ 1.12 ms/op under the exclusive guard at 32 × qd32.

**Never-lossy writeback:** flush units re-validate staged ownership per attempt and present the ino's CURRENT fencing generation; fencing-stale ⇒ contractual no-op; verified-NotFound (reclaimed ino) ⇒ discard orphans; transient ⇒ retry forever. **ENOSPC is terminal for a write that would CREATE custody** of a block no data volume can allocate (every placement candidate's allocator LATCHED exhausted by its own terminal `StorageFull`; an unreachable holder is retryable and never latches): refuse `ENOSPC` in the staged write path before any byte is recorded; custody the daemon already holds keeps the ladder. **The write cache's claim (amended 2026-10-22):** the ring is never the set's capacity in either direction — its residents' claim on the store (`staging.StoreClaim`: inline nothing, a packed slot, else a whole block) is what `df` subtracts from free and what every fresh custody is admitted behind (`enospc.storeCoversRing`: `free ≥ claim + the write's growth of it`), so `write(2)` answers ENOSPC before the cache holds what the store cannot (generic/750: 1,481 residents FAILED at the dismount of a filled 16 GiB scratch; generic/475: a 7 GiB memfd of them). The write-path allocation park under the block guard is wall-bounded (`2 × routine fence bound`, floor 1 s). Before this law a full volume made the daemon a RAM sink (74 GiB RSS on a 24 GiB volume).

**Write pipeline depth governor:** a runtime-derived BDP target (no fixed depth anywhere), a BBR-flavoured probe-up (launch on saturated epochs with budget headroom, adopt if delivery responds, retreat + duty-cycle cooldown on dead gain, bleed to 1.0 unsaturated), in-flight bytes a non-sheddable budget component; the overlay store takes the same permit; `write_pipeline_phase_ns` ten-phase residence histograms always-on.

**Block reclaim:** terminal frees `begin_free (retire incarnation) → tier purge → durability hold → finish_free (reallocatable) → RAM debt` — **the durability hold (amended 2026-10-24, decision 0003 §BT): a block freed by a metadata change returns to allocation, and to the device's discard, only once the record that freed it is durable** (landed AND covered by a barrier that completed after it, on every metadata member; ext4's law for the blocks its running transaction freed): under the ack point (§5.2) a truncate, punch or unlink is answered at its RAM apply, and a block handed on at that instant took another file's bytes while the old file's durable map still named it — a power cut replayed that map over them. A held free is supply in sight: `df` and the write admission count it free; the ENOSPC valve's drain pulls a barrier before it judges (a full store never answers ENOSPC while ≤ one flush interval of frees waits); a non-holder's shipped free is held the same way before it ships; with **discard elision** on block devices (discard is substrate hygiene, never correctness: unmapped blocks read zeros, reuse is guarded by write-before-publish + the incarnation word); elide while `debt ≤ virgin_bytes`; a paced single-lane drain above the watermark; idle drains to zero; `trim --full` discards the whole free list; a trim claim window = pending supply, never a deficit. The background reclaimer: pop-ownership exactly-once; demand-derived parallel blocking lanes grouped by device with adjacency-preserving chunking; the **manners law** (foreground device-byte movement + queue below cap ⇒ defer; at cap ⇒ drain; idle ⇒ full width); **park-don't-spill** (an at-cap enqueue parks event-driven, bounded `clamp(4 × batch ÷ measured drain rate, 50 ms, 1 s)`; cap `clamp(displacement rate × room latency, 4096, budget/1024 ÷ entry)`; device commands never issue from the enqueue context); the reclaimer observes the writer-guard fence latch (a fenced zombie never issues destructive discards). Ledger identity `queued + elided + held ≡ terminal frees` (`held` = `block_free_durable_held`, 0 at quiescence).

**Memory budget authority (R5):** components `{gauge, floor, weight, shed}`; budget = flag → cgroup `memory.max × 0.8` → 70 % RAM; `Σ floors ≤ 0.9 × budget`; Green < 80 %, Yellow 80–95 % (freeze growth), Red > 95 % (shed to weights; parked caps halve and become bounds; jobs pause loudly); hard backstop at 100 % for 3 ticks. Non-sheddable components: transport payload arenas, in-flight DMA, severed buffers, placed assemblies, zcrx areas; sheddable: hot tier, read LRU, hold, extents, job copy buffers.

### 6.3 The read path

Precedence: write-side overlays first (the accumulation buffer's coverage-aware snapshot; an open device-overlay record; extent records composed over the base; staged entries) — a dirty local authority outranks durable state. Then by layout: inline from the record; staged from the mmap; packed/striped resolve the mapping (**binding-validated**: bytes for key K serve block b only if the current map still binds b → K after the bytes are in hand) and walk: hot-block RAM tier (sharded clock, consumable `referenced` + sticky `protected`, refcount puts) → ≤ 256 KiB RAM LRU → read-lane hold → **the read cache** → NVMe read cache (mmap) → device. **ONE purge helper** covers all five tiers (a forgotten tier is a stale-serve class).

**The read cache (amended 2026-10-21, the owner's rulings; decision 0003 §BF).** SqueezeFS has TWO caches sized in percent of SYSTEM RAM, each default 25 (Lustre's `max_cached_mb` posture): `SQUEEZEFS_READ_CACHE_PCT` (this tier; 0 disables) and `SQUEEZEFS_WRITE_CACHE_PCT` (the staging ring in RAM). Both are components of the memory budget, which stays the ceiling: the percentage scales down with the budget's ceiling below the solo 70 % (a cgroup cage, a fleet share); Yellow freezes growth, Red sheds to the authority's target. Both are instances of ONE cache core (`mem/cache.zig`, `Cache(Entry, Sink)`): the read cache is `Cache(Grain, DropSink)` — on eviction the bytes are dropped, the device still has them; the write cache is the same core reversed, its sink promoting a resident before its memory is released. **The policy is plain LRU** (the owner's ruling: least recently used out first, at the cache's own bound and when the budget sheds; no CLOCK, ARC or frequency variant): exact within a shard — an intrusive list, a hit's touch O(1) under the shard's spin lock, no allocation per op — with the sharding its one approximation (the bound split evenly over `S` shards, keys hashed uniformly: a victim is the oldest of a 1/S slice, not of the whole). **What it holds**: the bytes a RANGED device read DMA'd — the 4 KiB-outward window of a random sub-block request — at the LBA grain (4 KiB), the one size every window is a multiple of, so a 4 KiB random read is one lookup and a deposit stores exactly the device bytes the read paid for; windows up to the ranged bounce slot (64 KiB). Whole-block fills stay the hot tier's. Every grain of a block lives in one shard (the key hashes the block), so a window serve, a deposit and a purge each take one lock. It serves FUSE reads whose first tier would be the device (`O_DIRECT` included; `direct_device_true` never) and the interposer's ring arm (the IPC host's probe is the same warm ladder call); the direct arm reads the device itself and sees no cache. **Where the fill lands**: the lane's ranged read deposits after its DMA (a bounce, one copy); the IPC host's direct-drive READ deposits its landed arena window at its CQE; the FUSE zero-copy direct leg lands in the app's pages this process never sees, so with the cache on the warm ladder declines it for a grain-eligible cold read and the lane fills (`SQUEEZEFS_READ_CACHE_FILL=lane`; `leg` is the control arm — zero daemon passes cold, no fill); a window serve is one memcpy into the reply (at 4–64 KiB a daemon copy beats a kernel bridge op, so no fd-source arm). The owed step is the leg that lands in the cache's own memfd slab and replies from it (`READ(device → slab)` + `READ_FIXED(slab → the app's pages)`): no lane hop cold, zero daemon passes warm. **The coherence law**: a grain is valid iff its block's incarnation word still reads the pre-DMA snapshot at the insert (the validation at the visibility point), the current map still binds the block after the copy (the binding recheck every tier serve makes), AND the filling inode's lease epoch still reads the value snapshotted BEFORE the DMA (`lease_epoch`; a moved epoch is a stale refusal evicted at the lookup). A local write invalidates through the ONE purge — an in-place write (W1, the in-place drains) through its RANGED face, exactly the rewritten grains, the whole-block tiers dropping the block; an overlay's displacement and a free the whole block. A FOREIGN write reaches the reader through the token recall, the same event the whole-block tiers and the kernel's page cache ride: the reader's recall sink purges every key the recalled layout names AND bumps the inode's lease epoch (a foreign write bumps it the way a local admission does) before it acks, so the holder's write lands only after the reader's grains are gone. A foreign in-place patch (zero-journal, size-neutral) reaches the reader when its parked stamp drains (the flush cadence) — the posture the hot tier and the kernel's page cache already had, stated. `read_cache_stale_served` is the must-stay-0 tripwire of the verify seam (`SQUEEZEFS_TEST_READ_CACHE_VERIFY`: every serve re-read from the device and compared). Misses: a random ≤ 256 KiB request on a passthrough volume not stream-classified with every probe missed ⇒ a **ranged** 4 KiB-outward DMA, straight into the registered reply window when aligned (**dest lease**: +28.6 % GB/s, CPU/byte −50 %), never published, never single-flighted; else a **result-carrying single-flight** whole-block fetch (≤ 1 device fetch per unique cold block; cohort waiters served from the primary's result), fed by a per-lane AIMD **prefetch** pipeline (start 2, ×2 on foreground wait, ÷2 on evicted-before-consumed; K = 4 offset lanes per file; ≥ 4 contiguous requests classify streaming) and a probe-governed **ahead lane** (both open-loop depth derivations were falsified by counted brackets). **Scan-resistant admission** (fills > 256 KiB): first-touch/streaming ⇒ hot-tier probation, disk publish SKIPPED (the tier-publish tax: 16.9 GiB of device writes to read 16 GiB once); ghost second touch (2^16-entry direct-mapped tag table, two-epoch) ⇒ protected + validated NVMe-tier publish; waste bounded `wasted_bytes ÷ device read bytes ≤ 5 %`. Every TIER fill is incarnation-validated before, during, after (a cached copy is of ONE generation of the block's seqlock word); a rebind-ladder exhaustion escalates to ONE serialized settle under the inode's meta stripe — the plane's (3.5) table every map publish holds — instead of EIO (`stale_binding_escalations`). **The lifetime law of a DEVICE-TRUE serve (amended 2026-10-23, decision 0003 §BI):** a ranged window, the escalated walk's leg and the settle deposit nothing, so the seqlock generation is not their law — an in-place write's retire → publish (W1, the in-place drains, a reservation's landing) moves it to evict cached pages, and under a sustained in-place storm on one block the word is unstable more often than stable (xfstests generic/095: 45 mixed writers on a 1 MiB file read EIO through the whole ladder and fired the settle's tripwire). Such a serve is valid when the block's LIFETIME read before its DMA stands after it (the allocator cell allocated under the same stamp; a key no allocator here tracks keeps the seqlock law) and the map still binds the block: its bytes are the device's at the DMA's instant — torn at the device's sector grain against a concurrent in-place write of the SAME file at most, Linux's O_DIRECT law for a direct read racing a direct overwrite — never another lifetime's. A deposit still waits for a stable generation. On a zc session the whole-block fill pool is ONE `MAP_SHARED` memfd slab so warm serves bridge `READ_FIXED(fd → slot)` with zero daemon passes (`SQUEEZEFS_READ_ZC_SERVE` default ON: daemon CPU/GiB −24 %). Hybrid I/O: O_DIRECT is NOT an admission class (a ranged second touch escalates to one admitted whole-block fetch); `-o direct_device_true` is the measurement ruler. Read copy ledger closure: `dest + bounce + dest_dma + zc_serve ≈ user bytes`.

**The zcrx read lane (optional, nvme-tcp fabrics):** a second userspace NVMe/TCP host association per device serving COLD read fills only (the kernel keeps writes, metadata, admin, multipath, recovery): one lane queue = one io_uring (`DEFER_TASKRUN|SINGLE_ISSUER|CQE32`) = one zcrx ifq = one NIC RX queue = one TCP connection; multishot `RECV_ZC` into a PMD-aligned NUMA-bound area; a streaming PDU parser (headers ≤ 24 B copied to a stack scratch; payload spans as `(chunk, off, len)` refs holding chunk refcounts); ONE gather pass fused into the caller's registered destination. Queue isolation: claim the highest-indexed RX queues (`clamp(devices, queues/4, queues/2)`), shrink RSS, ntuple-steer the lane's flows, verify header/data split, revert at disarm, sweep stale rules. Depth `min(MQES+1, clamp(cpus × 2, 4, 64))`; area = admitted window + MTU-grain delivery slack + the NIC ring's standing pool demand. Structural starvation tears the session down. Engagement law `gather ≡ fill`; `zcrx_lane_poisoned` must-stay-0. Measured: nvme-tcp RX copy was 55 % of client cycles at 46.6 GB/s; 4 queues at matched bandwidth 3.32 → 1.06 busy cores.

### 6.4 fsync

`fsync_phase_ns` exact-sum (`intent_barrier / data_flush / staged_promote / staged_sync / data_barrier / meta_publish / meta_barrier / extent_barrier / total`); barrier only the data namespaces the ino TOUCHED (a per-ino stripe word stamped at every layout publish and in-place DMA); write-through namespaces skip; independent legs joined and ALL awaited (never cancel a sibling); the intent barrier first, the staged record's ranged sync (§6.1 "Durability") and the data barrier strictly before the meta legs that name the blocks, the meta barrier last. `fsync` itself takes no inode write guard.

### 6.5 Compression and encryption

Per-volume `lz4`/`zstd` and AES-256-GCM/ChaCha20-Poly1305 declared at format; `process_write/process_read` at every write path; the key wrap is `hkdf-sha256/aead-kw/v2`: `PRK = HKDF-Extract(per-volume salt, key file material ≥ 32 B)`, `KEK = Expand(PRK, "squeezefs:key-wrap:v2:kek")`, `key_id = Expand(…, "key-id", 8 B)`, blob = `"SK" ‖ 0x02 ‖ nonce ‖ AEAD(KEK, aad = key_id, data_key)` = 63 B in every block header; config stores only `{scheme, salt, key_id}`; resolve `--encrypt-key` → `SQUEEZEFS_ENCRYPT_KEY_FILE` → `/etc/squeezefs/keys/<key_id>.key`; key file `O_NOFOLLOW|O_CLOEXEC`, owned by euid/root, `mode & 0o077 == 0`; `PR_SET_DUMPABLE=0`, `RLIMIT_CORE=0`; zeroize on drop. Transformed volumes reserve chunk headroom at format and refuse geometries that cannot hold `max_stored_image_len(block)`.

### 6.6 fallocate (added 2026-10-23, the owner's ruling "implement it"; decision 0003 §BH)

`fallocate(2)` is served in every mode the FUSE transport forwards, and its reservation is REAL: a reserved byte is charged to the volume the moment the call returns, and a later write inside it cannot `ENOSPC`. The representation is the **UNWRITTEN binding** (`layout.M_UNWRITTEN`, a flag on the 40 B mapping wire): a whole block allocated to the file — a durable reference like any other (`+ref` in the layout's transaction, counted by `df`, by fsck's census and by the allocator's recovery) — whose bytes are NOT the file's. Every resolve seam serves it as a HOLE (reads return zeros, W1 and the overlay decline it, every seed is zeros) and only two consumers see it: the admission's custody probe (a reservation is custody the file holds — admitted on a full store) and the whole-block landing's destination choice (`accumulate.pickDest`: a sole-owned reservation is written IN PLACE, the whole block under W1's fence pair — retire → DMA → publish — and the publish flips the flag: the SAME reference, no `±ref`, no proof, no mint, no free; a reservation an epoch binds, an open overlay record covers or a clone shares takes the fresh-mint path, whose publish displaces it — space-neutral after the commit). A reservation needs no DMA proof: the DMA-before-type-flip law exists so a flip cannot precede its bytes, and an unwritten binding names none. A 1 GiB fallocate is 256 mints and one publish per `MergeOutcome.max_displaced` blocks — no device byte. The tree-mapped map carries it as a kind-2 record.

The law per mode (`kv_fs.fallocate`, under the inode's EXCLUSIVE level-1 guard — a layout change, as a truncate):
- **mode 0 / `KEEP_SIZE` / `UNSHARE_RANGE`** — every striped block of `[off, end)` the map does not bind is reserved (`WritePath.reserveRange`); an inline range reserves nothing (the record IS the storage); a staged or packed file promotes to striped first (its image on its own block). Without `KEEP_SIZE` the size rises to `end` through the truncate-up path (§AL's extension zeros on a mapped EOF block, the size epoch, mtime/ctime). No reflink is exposed, so `UNSHARE_RANGE` adds nothing. Idempotent: a second reservation of the range changes nothing and stamps nothing. A truncate AT or below the size — the same size included, ext4's `ia_size <= oldsize` (generic/092) — clips every binding past the new EOF, a reservation as data; a grow keeps them.
- **`PUNCH_HOLE | KEEP_SIZE`** — `[off, min(end, size))` reads zeros and returns its space: the write custody settled first, the whole blocks inside leave the map in one transaction per `max_displaced` of them (`MapSeam.punch`: the inline map republished without them; a tree-mapped file's `kvmap.stagePunch` re-canonicalizes the straddling runs into their head and tail) and are freed after it; a partial head or tail inside a WRITTEN block is zeroed through the write admission (in place when W1 admits the piece; a hole's or a reservation's edge writes nothing; every byte of the range lies in exactly one of the head, the whole blocks and the tail — a range inside one block is ONE edge, `[off, upto)` when `off` is block-aligned: generic/695's `fpunch 8M 2M` on 4 MiB blocks); an inline record is rewritten with zeros, a staged or packed image re-staged with them. The size never moves.
- **`ZERO_RANGE` (± `KEEP_SIZE`)** — zeros without returning space: the edges as the punch's, every whole block of the range flipped to its unwritten twin (the same reference, no I/O, out of every read tier) or reserved fresh; without `KEEP_SIZE` the size rises as allocate's does.
- **`COLLAPSE_RANGE` / `INSERT_RANGE`** — at the BLOCK grain (`offset` and `length` multiples of the stripe block — the filesystem's block for fallocate(2)'s alignment law; a sub-block shift is EINVAL, as every extent filesystem answers it): the inline map re-indexed in ONE transaction, the data unmoved (`MapSeam.shift`; `Publish.shift` exempts the re-keyed references the old map already named from the proof law), a collapse's blocks freed after it, then the size commits under the size epoch. A tree-mapped head or a shift wider than one journal entry answers EOPNOTSUPP, counted, the map standing. **Linux's FUSE client forwards neither** (`fs/fuse/file.c` `fuse_file_fallocate`: `mode & ~(KEEP_SIZE | PUNCH_HOLE | ZERO_RANGE)` is EOPNOTSUPP before a request is formed, 7.3 and the 9.33 series alike), nor `UNSHARE_RANGE`: the daemon's arms are reached through the dispatcher alone until a kernel patch forwards them (owed).
- Every mode naming blocks up to `end` screens the u32 block ceiling (EFBIG); a volume-less set holds nothing past its inline bound (EFBIG); an immutable or append-only inode refuses EPERM (the inode-flags law); a foreign-slot file takes the striped arm throughout (its records ship to the holder); mtime/ctime stamp when the file changed.

Reclaim never reads a reservation (`scrub_unwritten_skipped`), the C2 repair recovers its allocator entry without a content check, the mover copies it flag and all, a rekey classifies it `none`. Must-stay-0: `unwritten_mapping_served` (an unwritten binding reaching the read choke point — a missed seam). The reference reserved nothing ("pre-allocation isn't strictly required in a sparse backend"; decision 0002 row 554).

## 7. The client bypass: LD_PRELOAD shim and native SDK

Control plane on the kernel mount; data ops on bound fds over same-host shared memory. On each `open` classify with one `fstatfs` (cached by `st_dev`); on a hit read the virtual xattr `user.squeezefs.il0` → `{abi, build_commit, abstract socket, path socket, nonce[32], flags}` (filtered from listxattr; EPERM on set). Snapshot-then-validate every descriptor; derive every checksum/compare from the severed private copy; direct-arena DMA only for uninterpreted bytes; lease-refcounted unmap; every wait on client memory bounded. Dedicated service threads (spawned on session admission up to `clamp(3 × cpus/8, 2, 64)`, the drain-lane width — one function sizes the direct-drive shards too), one session per thread for life. **Sync fast path for reads**: per-inode `try_read` → the guarded warm ladder → serve into the arena; demote (drop the guard FIRST) on miss or contention into an async handoff onto the FUSE per-core handler lanes (never a runtime inject queue: measured ~130 µs/op); a handoff every lane refuses WAITS in its owner's queue for a fiber slot — a read or write on a regular file never answers EAGAIN (amended 2026-10-24, decision 0003 §BU; EIO only past the fail-stop lattice's bound). Bail-out ladder: every interposed symbol is indistinguishable from the real call under every failure; `mmap` on a bound fd unbinds every in-process binding of that inode + invalidation; `fork` child flag-poisons and `close(2)`s (never `shutdown`) the socket; bindings refcounted across dup'd fds; a bound-fd offset mirror flushed to the kernel at every transition out of authority. Sessions per mount `clamp(cpus/4, 2, 16)`; arena `max(64 MiB, cap/population)`; admission cap `budget/8`. Measured: warm 1,017,548 IOPS, device-true 622,112. **The hybrid lane gate**: ops above a derived threshold (`memBW × 2.3 µs / 2 copies`, ≈ 140–164 KiB) route to kernel FUSE for throughput. **SDK**: the same wire as a second client kind; positional-only ops on arena-backed 4 KiB-aligned buffers under a buffer-lease law (`free` while SUBMITTED = EBUSY, never deferred; poison ⇒ never recycled); versioned over a one-release window; strengthen-only per-open durability.

**The direct arm (amended 2026-10-20, decision 0003 §AX).** `-o interception=direct` is the mount owner's opt-in to a TRUSTED-client mode: a session whose uid could open every data device node (the daemon's screen at HELLO; the client's own `open(2)` the final word) reads the data devices itself — a layout LEASE per bound fd (`ino → {size, epoch, block → (volume, device offset)}`, a resident striped passthrough file with no write-side custody), ONE `pread` on the device from the caller's thread, then the recheck: the inode stripe's epoch, in a sealed page the daemon shares read-only, still reads the lease's AFTER the bytes are in hand — the §6.3 validation, client-side. The daemon bumps the epoch after every RAM apply that changed the inode's record or xattrs (before the ack, every origin) and at every write's admission; a moved epoch drops the lease and asks again; holes, tenants, inline/staged files, transformed volumes, multi-block and unaligned requests, and every write stay on the ring. The trust granted is whole-device — the trust a FUSE mount's root already holds — and is for the owner's own clients; DAOS's libioil has no equivalent (its engine does the I/O), this is the step beyond it. A dead daemon poisons the session through the heartbeat before any read under a lease nobody can invalidate. **Writes (amended 2026-10-20, decision 0003 §AY):** on a session whose uid could also WRITE every data device node (`FEATURE_DIRECT_WRITE`), a binding with write rights may hold a WRITE lease — granted only when every mapped block passes the W1 patch's own eligibility (sole-owned, undecorated, passthrough, no custody), marked so that the daemon's tiers deposit nothing for its keys and its mover stays off them (the inode is device-true while the lease stands) — under which an aligned, in-size, single-block write is ONE `pwrite` on the device from the client's thread. The lease is a token the daemon RECALLS before every mutation of the inode (a kernel write's admission, an exclusive guard, a layout RMW): recall := 1 then read the client's in-flight count (Dekker, SeqCst on both sides; `WriteLeaseModel`); zero ⇒ proceed at once, else wait for the count to drain (bounded at 1 s, then FORCED and poisoned — the one lossy case, loud). The postlude (the parked Δ(mtime, ctime) stamp, KD-11's notify, the fsync touch) is a batched note, acked at `fsync` — which the shim interposes: the note, `fdatasync` on the devices written, then the kernel's FSYNC. Durability: an acked direct write is on the device whatever dies next (the client, the daemon — the layout did not change under it); a cut keeps every write flushed before it. Security is unchanged in kind: the device-permission screen with the write bit, the client's own `open(O_RDWR)` the final word; a direct client could already read any block, writing extends the same whole-device trust.

## 9. Concurrency model and executor (Zig)

**No third-party async runtime.** Build a first-party, waker-based executor:
- **Per-core FUSE handler lanes** (one per queue CPU; data-class handler polls run here; handoffs from service threads target the lane homed on the destination CPU/node) and one **driven lane per drain worker** (no thread: the worker's pass runs the namespace class's handlers on it).
- A small **metadata pool** (`sqz-meta`) for plane-critical tasks (conveyor pass, checkpoint/SMO, publish pass, writeback, fold, reclaim).
- One **journal lane OS thread per writable volume** owning that volume's io_uring and parking in it.
- A **blocking pool** (`cap = cpus × 16`, floor 8) for offload; **thread-per-connection** for wires; per-queue threads for zcrx pumps; `main` drives the CLI with a thread-park `block_on`.
- Timers and fd readiness for lane-resident tasks live on the lane's own ring (a per-lane binary heap with cancel-safe tombstones; `POLL_ADD` one-shot per await) so a parked lane is only ever woken by its ring; a single **timer thread** (binary heap + condvar, cancel-safe tombstones) serves the non-lane contexts (main, the blocking pool). (Amended 2026-10-06, decision 0003 §D Q-B: the reference's global timer thread and epoll fd-watch thread paid a cross-thread wake hop per arm.)
- Primitives: async mutex/rwlock with **no ownership assignment to sleeping waiters** (release flips free and wakes the queue front; woken waiters re-contend) and a built-in **2 s ticked backstop** on every unbounded park (a lost wake self-heals; `lock_ticked_reregisters` counts it — 0 healthy); **bounded barging** (a fresh attempt takes a free lock only when nobody is queued; a queued waiter's re-contend barges; write-preferring); channels (oneshot/mpsc/watch) whose waiters register under the lock senders mutate under; notify with permit + epoch and synchronous enable-then-recheck; semaphore under the barging law; single-flight; once-cell with cancelled-leader re-election; a task set with genuine cancel-on-drop. Laws: stop latches, never abort from outside; every loop pinning the filesystem has an exit edge; cancellation of a committer is designed OUT (a dropped admission leaks ring budget forever) — passes run detached and panic-guarded.
- **Model-check every lock-free core** (write them as standalone, dependency-free modules checked by an exhaustive interleaving explorer; record the weakening that fails each model): the journal reservation (admission + reservation jointly, no over-commit), node lifecycle (`clean → dirty → serializing → superseded`), the payload-lease commit gate, the completion doorbell, the commit door and lease gate Dekker pairs, the W1 clone/patch fence pair, the slot-lease table, the park gate, the grant table, shared-ref marks, the conveyor handoff, the custody revoke pair.

## 11. Engineering discipline
