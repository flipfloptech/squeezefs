## 1. What landed (round 1 — items 1, 3, 4, 5, 6, 7 are SUPERSEDED where §8 says so: the markers name stripe 0, `D`'s tree is a permanent secondary home and mutations re-home first, `rmdir` is ONE intent, `XV_MAX_STEPS` = `2 × MINT_SPREAD + 8`, C17's confirm pass runs one census)

Under the armed plane a hot shared directory `D` spreads its dentries over `K` **stripes**, and the creators' ships spread over the stripes' holders instead of pooling at `D`'s (design §5.6.5 — the D1 shared-output shape's cure):

1. **The stripe ino and the map** (`src/meta_backend/dir_stripe.rs`, the ONE module; every arm of `meta_backend/mod.rs` calls into it). `K` stripe inos `D_0 … D_{K-1}` are ordinary `S_IFDIR` records with no name, each minted in a DIFFERENT creator's slot **on `D`'s volume** (so every stripe shares `D`'s seeded dentry hash — one seed, one order). The map is **`K + 2` reserved-name dentries in `D`'s own tree**: `\0sqz.stripe:NN → D_i`, `\0sqz.migrating → D` (the lazy migration's durable cursor), `\0sqz.striped → D` (the COMMIT marker — the map is live iff it exists). A leading NUL byte is a name no user operation can pass (the VFS refuses it), so the space is reserved by construction; the ONE routed pager filters the markers out of every listing. `stripe(name) = hash54(name) % K` over the volume's seed (`stripe_of`); `K` = `SQUEEZEFS_SYM_DIR_STRIPES` explicit, else `MINT_SPREAD` (64), clamped to `STRIPES_MAX` = `MINT_SPREAD`.
2. **The flip** (`stripe_dir` / `flip_dir`): the directory's holder asks the `K` heaviest foreign creators for one stripe each (`MetaCall::SupplyStripeIno { dir, index, supplier }` — the supplier mints a nameless directory in its own rotor slot and answers the ino; a creator that declines or is gone is replaced by the next; the remainder the holder mints in its own slots), then writes the map as **ONE PR 6 intent (`XvOp::StripeDir = 7`) of `K + 2` existing `InsertDentry` steps with the commit marker LAST** — no new step kind, no new applier (`xv_apply_step` stays the ONE); the intent's guards cover `I{D}` + every marker's `D{}` key (the coverage law at a served holder). A kill at any of the `K + 2` windows leaves NO live map and one open intent; the next lessee's roll-forward completes the WHOLE map. Triggers: **automatic** (`flip_due`: the directory received shipped inserts from > 1 distinct creator — the shipped child's slot holder is the creator identity — and the ship count over the `T_idle` half-window pair passed `N_floor`, the S4 dominance threshold), **explicit** (`setfattr -n user.squeezefs.stripes -v K D` — `clamp_explicit_k`; `getfattr` answers the K in force), **`-o stripe_dirs`** (every `mkdir` flips its directory at creation — the "12,500 jobs each mkdir under one root" shape).
3. **Lazy migration** (`migrate_dir`): the directory's existing names re-home by hash — insert into the stripe FIRST, remove from `D` second, each pair one intent — then the `migrating` marker is removed LAST; `dir_stripe_migrated_names` counts the moves. While it runs a name may be in BOTH homes and is served from the **stripe** (`stripe_locate`: stripe wins, `D` is the fallback; the EEXIST screen at create covers both homes). A successor lessee finds the marker at the directory's next access and resumes.
4. **The routing** (`meta_backend/mod.rs`): `lookup`/`create`/`unlink`/`link`/`rename` key the stripe as the parent (`stripe_insert_parent` — a create into a foreign-held stripe is PR 6's shipped `InsertDentry` with the stripe as its key parent, `dir_stripe_ships`); `..` from a stripe-resolved child answers `D` (`stripe_parent_dir`); `readdir` is the **K-way merge** of the stripes' pages in the shipped `(hash54, coll)` cookie order — the shipped cookie is the exact continuation (`readdir_striped_page`, `dir_stripe_readdir_merges`); `getattr(D)` folds `nlink = D.nlink + Σ(D_i.nlink − 2)` and `mtime/ctime = max` over the stripes, persisting the fold onto `D`'s record when a stripe's time passed it (`dir_stripe_time_batches`) — a stripe's own record is the exact delta its inserts wrote in the same tx as the dentry, so **nothing ships per insert**.
5. **`rmdir`** (`prepare_striped_rmdir` → `unlink_at` → `finish_striped_rmdir`, the trait `unlink` face): `D`'s exclusive 4a guard + guards on every stripe (travelling to their holders) → the live counts read → **a DYING mark** on every stripe (`SetNlink 2 → 0`, one intent) BEFORE the `IsEmpty` probes (`MetaCall::IsEmpty { dir, scope }` at a foreign stripe's holder, local otherwise) → the markers removed with `D` → `DestroyStripe` at each holder (`MetaCall::DestroyStripe { stripe }` refuses `EBUSY`/`ENOTEMPTY` on a live or non-empty stripe). An insert into a marked stripe refuses `ENOENT` at its holder (`refuse_dying_stripe`, `dir_stripe_dying_refusals`) — R26's race closes AT THE STRIPE; a failed probe revives the marks (`abort_striped_rmdir`).
6. **The wire**: `MetaVerb::{SupplyStripeIno = 0x90, IsEmpty = 0x91, DestroyStripe = 0x92}` — the PR-7b block, `IsEmpty` a read verb, the other two `mutating()`; `MetaReply::{StripeInoSupplied { ino }, Empty(bool)}`; every wire integer screened against durable state before effect (`serve_supply_stripe_ino` — the directory exists and is a directory, the index is below `STRIPES_MAX`, the supplier names this appender; `serve_destroy_stripe` — the record's shape). `CLUSTER_WIRE_SCHEMA` stays 5 (the program's unreleased wire); `XV_MAX_STEPS` = `MINT_SPREAD + 8`.
7. **fsck C17** (report-only, `fsck_stripe_findings` must-stay-0): the marker census rides C9/C10's ONE dentry pass (`RefPass.markers`), evaluated after C16 — `MultiplyMapped` (one stripe ino in two maps), `MissingStripe` (a map entry whose stripe has no record), `IncompleteMap` (a commit marker with fewer than `K` stripe entries), `MisroutedName` (a name in stripe `i` whose hash names `j`), `UnmigratedName` (a non-marker name in a striped `D`'s own tree with the migration flag gone) — confirmed by a fresh re-read of the striped population alone (`c17_still_holds`); repair refuses (report-only, C8's posture). The missing-stripe shape is also C10's dangling dentry, by construction.
8. **The Striping family** on the stats inode — `dir_striped_dirs`, `dir_stripe_flips`, `dir_stripe_supply_rpcs`, `dir_stripe_ships`, `dir_stripe_readdir_merges`, `dir_stripe_migrated_names`, `dir_stripe_time_batches`, `dir_stripe_dying_refusals`, `dir_stripe_rmdirs`, `fsck_stripe_findings` — appended after the Cross-owner family, 0 on every unarmed mount by construction.
9. **The knob** `SQUEEZEFS_SYM_DIR_STRIPES` (int, `1..=MINT_SPREAD`, derived default 64; **`1` = OFF** — no automatic flip, no xattr opt-in, no `-o stripe_dirs` flip; an already-striped directory still routes by its map, since its names would vanish otherwise), the mount option `-o stripe_dirs`, the xattr `user.squeezefs.stripes` (admitted by NAME beside PR 7's `gather`).
10. **The contracts** (§2), the fuzz arm (`cluster_wire_frame` 3c: the marker codec's totality, the 0x90 block's round trip through `MetaReplyFrame`/`MetaOpResult`) + its proptest mirror (`dir_stripe_marker_codec_is_total`, `dir_stripe_function_stays_in_range`, `dir_stripe_verbs_round_trip_the_meta_ship_body`), the docs (`docs/operations.md`, `AGENTS.md`, design row 7b + §5.6.5 as-built + §7.1).

## 3. Found and fixed before landing (the contracts' work)

1. **The flip's guards covered `I{D}` only** — a served `InsertDentry` at the directory's holder needs the marker's `D{D,name}` key covered by the travelling scope or it TAKES it, and under PR 6's coverage law a step whose key the scope should have covered parked at the holder for the wire's 10 s bound (contract 12's first run). The intent's guard set is now `I{D}` + every marker's `D{}` key; `remove_stripe_markers` takes the same set.
2. **`rmdir` removed the markers BEFORE `D`'s own removal**, so a create racing the rmdir found `D` un-striped and landed in `D`'s own tree — then the rmdir failed `ENOTEMPTY` with the stripes already destroyed (contract 6). The markers now go in `finish_striped_rmdir`, after the unlink; `abort_striped_rmdir` revives the dying marks on any failure before it.
3. **The `..` hop** passed the stripe's LOCAL ino to `find_parent_of_child`, which takes the GLOBAL one — a child's `..` answered a wrong parent under a guest slot (contract 9).
4. **The K-way merge lost names**: each stream's `readdir_page(max)` counted the directory's markers against `max`, so a page of 7 over `D`'s own tree during migration returned fewer than 7 real names and the merge's continuation skipped past them (contract 3). `page_names` pages to `max` NON-marker entries per stream.
5. **The background migration never ran** after an in-process flip: `kick_migration` was called while the flip still held the directory's `in_flight` slot, so the kick saw work in flight and returned. The kick moved to after the slot's release.
6. **`IsEmpty`/`DestroyStripe` decided foreignness by the lease GATE** (`served_here`), which a declared region's slot passes in-process, so contract 12's rmdir probed locally and shipped nothing; the predicate is now PR 6's own — `holder_of(stripe) != own_appender_id()` off the lease TABLE.
7. **The supply gauge read 0**: `DIR_STRIPE_SUPPLY_RPCS` was counted on the wire arm only; a supplier in this process mints directly. The count moved to `mint_stripe_in_slot`, the one mint every supply runs.
8. **The wide wave leg's volume**: 31 declared holders at 256 KiB nodes exhausted a 64 MiB volume's extents at the open (`ENOSPC` with the compaction reserve intact — 31 rings + their slot trees); the harness scales the volume with the node size so the extent population is the default leg's (§4 row 1b).
