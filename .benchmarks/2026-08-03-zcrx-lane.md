### 1.2 The bracket (30 s rows unless stated; busy cores = (usr+sys+irq+soft)% × 32)

**R1 — single queue, 4 conns, open-loop (A-B-B-A):**

| leg (order) | GB/s | busy cores | DRAM read B/B | receiver core |
|---|---|---|---|---|
| copy A | 10.21 | 1.42 | 0.61 | stime 29.84/30 — **copy-core saturated** |
| zcrx B | 20.93 | 1.81 | 0.035 | 74 % of one core |
| zcrx B2 | 22.21 | 1.79 | 0.036 | — |
| copy A2 | 10.33 | 1.42 | 0.63 | stime 29.86/30 |

**~2.1× single-queue ceiling**, order-independent. The classic side's
ceiling IS the copy core; zcrx's DRAM-read collapse (0.63 → 0.036 B/B)
is the copy pass and its read-back gone.

**R2 — single stream (1 conn):** copy 8.18 GB/s (0.61 core in the
copy) vs zcrx 10.71 GB/s (0.27 core; DRAM-read 0.021 B/B) — +31 %,
sender-side TCP bound.

**R3 — 4 queues @ 1 port, matched at port line rate (24.79 GB/s BOTH
modes; 2 sender nodes):**

| mode | busy cores | DRAM read B/B | DRAM write B/B |
|---|---|---|---|
| copy | 3.32 | 0.50 | 1.07 |
| zcrx | 1.06 | 0.018 | 0.54 |

**−68 % CPU at identical throughput.**

**R4 — dual-port, 4 queues/port, NUMA-matched receivers, matched at
NIC line rate (49.46 / 49.56 GB/s):**

| mode | busy cores | DRAM read B/B | DRAM write B/B |
|---|---|---|---|
| copy | 7.94 | 0.69 | 1.07 |
| zcrx | 2.75 | 0.035 | 0.60 |

**−65 % CPU at 49.5 GB/s** — the whole-NIC-fabric shape. What remains
on the zcrx side is softirq/page-pool machinery (soft 5.1 %), not
copies.

### 1.3 GO adjudication

The charter bar (≥ ~2 GB/s class win) is met with margin on every
shape: the single-queue ceiling doubles (+11–12 GB/s class), and at
line-rate-matched shapes the deleted copy converts to **≈ 5.2 freed
cores at 49.5 GB/s** — on the FS rows, where the RX class is 16–26 %
of all client cycles (26 % on the il row, the largest term), this
brackets the frontier ranking's **+3–5 GB/s kern-read projection and
raw-ceiling → line-rate movement** as real. Phase 2 entered.

## 2. Phase 2 — PR Z1 (this branch): design + contracts + the lane core

`docs/design-zcrx-read-lane.md` (Rev 1) pins the product shape: a
**userspace NVMe/TCP mini-initiator owned by the daemon, COLD READ
FILLS ONLY** (kernel nvme-tcp keeps writes/meta/admin/recovery), zcrx
receive on the daemon's own rings, serve-from-refcounted-area-chunks
via the gather law (the ONE lawful serve pass becomes a gather; the RX
pass is deleted; ledger closure stays byte-exact), derived sizing (no
fixed constants), NUMA/steering/R5 laws, and **read-only by
construction** (the codec has no write/reservation encoder — the
D0/fencing surface is unreachable). PR ladder: Z1 (this branch) →
Z2 (zcrx recv backend + steering netlink + field engagement + soak) →
Z3 (gather-serve + NUMA placement + default adjudication).

Shipped in Z1 (`src/zcrx_lane/`):

* **PDU codec** (`pdu.rs`): ICReq/ICResp (digests-off negotiation law —
  a controller demanding digests refuses the arm loud), Connect /
  Property Get/Set / Read capsules, C2HData with the
  `plen == pdo + datal` geometry law, CQE phase-bit stripping.
* **Mini-initiator** (`initiator.rs`): admin association (Connect
  cntlid 0xFFFF, KATO 0, CAP → CC.EN → CSTS.RDY), N IO queues (one TCP
  connection + reader/writer task pair each), CID pools with semaphore
  backpressure, sub-command chunking at the sysfs-resolved MDTS face,
  completion by CapsuleResp OR C2HData SUCCESS elision, the exact-length
  completion law (short data + success status = framing violation,
  never partial data), per-op error ≠ session poison, framing
  violation ⇒ poison loud + tripwire, and the **timeout quiescence
  law**: a timed-out op aborts-and-joins the queue tasks before its
  destination buffer can recycle (no zombie writer into pooled memory).
* **Probes** (`probe.rs`): `RECV_ZC` io_uring opcode probe (raw value
  58 — the crate's opcode list predates it), sysfs nvme-tcp discovery
  (`transport/address/subsysnqn/nsid/logical_block_size/
  max_hw_sectors_kb`), `/etc/nvme` host-identity parity.
* **Funnel wire-in** (`nvme_dev.rs`): eligible pooled fills offered to
  the lane first; disarmed/ineligible/error ⇒ the uring worker
  unchanged; lazy arm (OnceCell, one association per device node).
* **Gauges** (stats inode): `zcrx_lane_armed`, `zcrx_fills`,
  `zcrx_fill_bytes` (the engagement instrument — a lane row is INVALID
  unless its delta accounts for the row's cold-fill bytes),
  `zcrx_fill_fallbacks` (≈ 0), `zcrx_frame_violations` (must-stay-0
  tripwire), `zcrx_conn_errors`, `zcrx_hdr_copy_bytes` (the priced
  header edge copy).

**Copy-ledger extension (design §4.4):** lane fills do NOT increment
`read_fill_dma_bytes`; `zcrx_fill_bytes` is the new fill-provenance
term, so extended closure reads *every served byte's fill provenance ∈
{pooled DMA, zcrx area, dest DMA}* and the serve-side law
(`dest + bounce + dest_dma ≡ user bytes`) is untouched — the Z3
gather-serve counts in `read_copy_dest_bytes` exactly as today.

## 3. Contract coverage (tests/zcrx_lane_tests.rs — 20 tests, in-process mock NVMe/TCP target)

Codec laws (wire layouts, geometry, negotiation refusals); association
+ multi-PDU reassembly byte-exact vs the mock namespace; sub-command
split; SUCCESS elision; PDO padding skipped AND priced; concurrent
reads complete by CID; per-op controller error ≠ poison; framing
violation ⇒ poison + tripwire; unaligned-range ineligibility; funnel
engagement + **byte-exact gauge closure** (varied sizes incl. splits:
`zcrx_fill_bytes` ≡ Σ served, one fill per funnel read); per-op lane
error ⇒ **kernel path serves the op** + fallback counted.

**The fallback contract is the one local gates actually exercise** (no
zcrx-capable NIC on the dev box or CI): disarmed default is
byte-identical and gauge-silent, and `SQUEEZEFS_ZCRX_LANE=1` without
the Z2 backend refuses the arm LOUD and stays on the kernel path —
proven by tests, not by absence.

**Red-first record:** the funnel-engagement/closure/fallback contracts
were verified RED by running the suite with the `nvme_dev.rs` wire-in
stashed (3 FAIL / byte-identical law PASS), then green at `615b7ab`.
The suite also caught a real framing bug red before any field exposure:
the reader consumed 16 bytes past a CapsuleResp header (hlen 24 already
carries the CQE), desynchronizing the stream — every
CapsuleResp-completed read hung to timeout while SUCCESS-elision paths
passed. Mock-target fidelity earned its keep on day one.

**Z2-deferred contracts (named, not silently dropped):** refill-ring
discipline and R5 area budgeting are properties of the zcrx recv
backend (field-NIC-only mechanics) — their laws are pinned in the
design (§5, §8: 1:1 ring sizing so recycling never stalls mid-stream,
admission-bounded in-flight fills, area as a non-sheddable R5
component registered at arm) and their tests land WITH the backend.
The Phase-1 bench already demonstrates both mechanics live on the
field NIC (1:1 refill ring, 512 MiB areas, 200 M+ chunk recycles,
zero stalls).

## 6. Projections the reformat-window bracket should confirm (from §1 + the frontier pricing)

  is the upper bound the FS rows draw down from.
