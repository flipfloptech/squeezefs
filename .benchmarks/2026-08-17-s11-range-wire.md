## Key decisions

- **Extension keeps the surviving token and grant identity** (mints
  nothing): the client's cached token, every in-flight write fencing on it,
  and the release identity all stay current; the widened record repositions
  in the sorted list and `retire` gains a token-keyed O(n) fallback
  (correctness over constants at the §9.2-bounded population).
- **The merge never absorbs a second live record** (its release handle is
  outstanding): other same-scope grants clip the window like foreign walls;
  a required window overlapping ≥2 own grants is the loud `BridgeRefused`
  (a covering-cache client never builds it).
- **Budget derivation**: `R5 budget / 256`, floor 16 MiB — the floor is
  §9.2's own arithmetic (the 1 TiB block-cyclic decomposition ≈ 12 MiB of
  spans; a share below it would refuse the workload S11 exists for — the
  Issue-19 class). No env knob; `test_swap_range_table_budget` is the seam.
- **EX-only issuance** (KD-MW-9 v1): `acquire_lock_range` has no mode
  parameter; CW stays on the seam-armed moded path.
- **`SQUEEZEFS_RANGE_CUSTODY` ships default-OFF** — the adjudication below.

## The live leg (`s11-range`) — three findings, and the verdict

The leg found three real bugs before its first green custody pass (the
crucible doctrine working at N=2):

1. **The fd-less truncate lease strand** (fix `2deae4ce`): the authority's
   `truncate(2)`-shaped SETATTR (the MPI rank-0 create-truncate shape)
   cached a whole-file lease with no open episode to release it; on an mw
   mount the daemon's lock table IS the custody arbiter's table, so BOTH
   co-writers' first range acquires starved into EIO forever. Fixed
   (mw-armed + no open handle ⇒ release at op end; ftruncate and solo
   postures byte-identical), repro-ported red-first
   (`tests/mw_truncate_lease_strand_tests.rs`, RED verified against the
   reverted fix).
2. **The own-grant matrix misclassification** (fix `3260a395`): `plan_range`
   classified the holder's OWN EX grant through `!compatible_with` — the
   §6.7 matrix governs two DIFFERENT holders, and EX‖EX is incompatible by
   it — so every frontier-crossing writeback chunk read as FOREIGN custody
   and a LONE streaming co-writer starved on itself (proven live twice; the
   staggered single-writer probe eliminated the overshoot hypothesis).
   Fixed (mergeable = same scope + same mode), repro-ported red-first
   (`own_grant_partial_overlap_extends_and_covered_reask_serves`).
3. **The concurrent same-ino publish composition is rungs 16/17's owed
   machinery** (adjudication `514b94f3`): with custody working, two
   co-writers' layout publishes on ONE ino race the delta-chain/full-save
   base — the §6.2-item-9 divergence refusal fires ("the writer must
   refetch its base and recompute" — the refetch arm is
   `docs/design-mw-layout-versions.md` §6's NAMED not-yet-built residual,
   owned by the S9 publish surface = rows 16/17), the chain-cap full save
   re-bases from a private RAM view, and fsync-acked bytes are
   composable-away. **Bit 15 + the C8 oracle DETECT it exactly as designed**
   (drift 702 on the first capture, 4830 on the final pass; sub-block zero
   runs in the cold image). The **whole-file-custody control run is
   byte-identical** on the same venue/shape (a 64 MiB buffered co-writer
   stream cold-verified via the peer), and the **solo-ranged control is
   byte-identical** — the loss needs BOTH range custody AND a concurrent
   peer on one ino, i.e. exactly the §9.1(d) composition the design stages
   to rungs 16/17.
