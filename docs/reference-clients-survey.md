## Executive summary

Both references converge on the same FUSE-layer levers SqueezeFS's metadata program (M1–M12) already targets — negative-dentry TTLs, clean-handle FLUSH elision, submit batching — which **independently validates the program's design choices**. The genuinely new material is concentrated in **recovery/ops machinery** and a handful of caching knobs:

1. **P1 — SETATTR time-echo absorption** (JuiceFS): size-changing SETATTRs absorb the ctime/mtime bits into the truncate tx and return early (`vfs_unix.go:159-168`); mtime flushes are absorbed into the writer (`writer.UpdateMtime`). Directly addresses the just-found kernel ctime-flush SETATTR echo doubling SqueezeFS rename/unlink journal entries; belongs beside D4/M6 (journal-entry economy, gate G4 ≤ 1.05 entries/op).
2. **P1 — External mount watchdog + FUSE-connection abort** (JuiceFS `cmd/mount_unix.go:109-283`): supervisor stats a control inode every 5 s; on 30 s of unresponsiveness dumps kernel stacks, SIGABRT→SIGKILLs the daemon, and writes `/sys/fs/fuse/connections/<minor>/abort` to unwedge blocked callers. Complements the landed M4 in-daemon watchdog, which can log a wedge but not clear one.
3. **P1 — Operator-tunable kernel-cache TTLs** (both): attr/entry/dir-entry/negative TTLs are first-class knobs (JuiceFS flags; DAOS per-container attributes). SqueezeFS hardcodes 1 s and actively filters user-passed `entry_timeout`/`attr_timeout`/`negative_timeout` (`src/fuse_client.rs:7310-7325`). Trivial to land with M5.
4. **P2** — metadata **fsck/scrub + dump/load** (SqueezeFS `run_metadata_fsck` is a stub); **automatic metadata backup** (JuiceFS `pkg/vfs/backup.go`); **staging/read-cache disk health state machine** with bypass + auto-rejoin (JuiceFS `disk_cache_state.go`); **kernel readdir caching** (`FOPEN_CACHE_DIR`); **seamless-upgrade FUSE fd handover** (research: over-uring re-arm).
5. **P3** — LD_PRELOAD data-path interception (DAOS libioil/libpil4dfs) as the only proven escape from the ~18 µs/294 k-IOPS FUSE transport ceiling; proactive kernel-entry invalidation for idle-resource decay at 15 k-node scale.

## DAOS client (dfuse + libdfs + libioil/libpil4dfs)

**Architecture sketch.** `dfuse` is a libfuse(-fork "fused") lowlevel daemon: N blocking `fuse_session_receive_buf` threads (default `min(cores,16)`, `dfuse_thread.c:31-60`, `dfuse_main.c:608-643`) hand async work to per-EQ DAOS event-queue progress threads (default 1 EQ) with slab-allocated request events (`dfuse_core.c:1449-1575`). Data ops become async `dfs_read`/`dfs_write` against DAOS objects; there is no local block cache — caching is delegated to the **kernel** (attr/dentry/data TTLs per container) plus targeted daemon-side fast paths (pre-read, chunk coalescing). The interception libraries (`il/`, `pil4dfs/`) LD_PRELOAD-hook libc and route data ops straight to libdfs, keeping dfuse only for control/compatibility. Client-side crash *recovery* is thin by design (server-side DAOS handles durability; `dfs_cont_check` is the offline fsck).

## JuiceFS (Go FUSE client, object storage + Redis/SQL/TiKV metadata)

**Architecture sketch.** One Go daemon: go-fuse raw server (`pkg/fuse`) → `pkg/vfs` (handles, file readers/writers) → `pkg/meta` (pluggable engines: Redis/SQL/TiKV, one `baseMeta` with per-engine `shouldRetry` transactions) + `pkg/chunk` (object-store `cachedStore` with RAM pages, disk cache, writeback staging, prefetcher, singleflight). Files = 64 MiB chunks = append-only **slices** (id from meta) = ≤ 4 MiB blocks in object storage; mutation is slice-superposition compacted in background. Sessions are first-class meta records with heartbeats; recovery tooling (fsck/dump/load/backup, supervisor watchdog, seamless upgrade) is unusually rich because the client is the *only* stateful FS component.
