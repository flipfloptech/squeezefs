## 3. The LTP venue failure (not a red)

Attempt 3's LTP leg exited in one second at 02:34: `make: *** No rule to
make target 'autotools'`. The LTP source tree the runner keeps at
`/tmp/ltp_build` had **aged out under systemd-tmpfiles** (directories dated
Aug 30, every file gone; the installed test binaries under
`/tmp/ltp_install` survived because the 1.2.2 run touched them). The runner
saw the hollow directory, skipped its clone, and configured nothing. Repair:
the hollow tree moved aside, a fresh clone, `make autotools` + `configure`
with the autotools already in the nix store (`automake`, `autoconf`, `m4`,
`pkg.m4` — on no default `PATH`; how the Aug 30 tree was configured). The
chain then RESUMED from the LTP leg on the same tip
(`/tmp/release-1.2.3/driver-resume.sh`): the product under test is
unchanged, so the three earlier greens on `86eff517` stand — a venue repair
is not a fix under the counted-run law. Board item: the runners' `/tmp`
trees are subject to the age cleaner; detect a hollow tree and re-clone, or
pin them somewhere durable.

  pinned `=0` (`cc8258b9`); five sibling contracts had been re-stated the
  same way with the flip (`fe714e6b`).

  ~2 GiB VmHWM jump on ~1 in 15 gate runs — ATTRIBUTED: the `--all-features`
  build's `dhat::Alloc` does not override `alloc_zeroed`, so the default
  `alloc` + `write_bytes` touches every page of the lazily-built read-fill
  pool (`block_pool_capacity_from(32)` = 512 × 4 MiB = 2 GiB) the first time
  a background fetch reaches it inside the measurement window. The warm-up
  now forces the pools (0/25 red, was 2/20). `3c71742e`.
- `conveyor_completion_hop_tests` measurement row: the 5 % span-identity
  band applied to rows run under a deliberate 2×-cpus spinning hog (−7.2 %
  observed — a run-queue wait between two threads' stamps); the un-hogged
  rows keep 5 %, the hog rows get 25 %. `3c71742e`.
