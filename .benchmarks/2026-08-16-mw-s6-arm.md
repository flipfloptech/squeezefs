## S6-b — self-fence clock law under duress (netem 200 ms + SIGSTOP)

Victim m31 remounted into its own netns, netem 200 ms per veth end
(renewal RTT +400 ms), re-joined THROUGH the shaped wire (duress, not
partition), census settled, then SIGSTOP (frozen daemon, running clock).

* Owner (while the victim was frozen): `member '4fa3eee7…' (reader)
  EVICTED … lease TTL 45s expired; lease epoch 32 is dead and its
  offsets are quarantined until proven drained (DLM S6 → S7)` +
  `custody dead-epoch:1 declared DEAD` — the S7 mint, uuid-keyed.
* Victim (1 s after SIGCONT, on ITS OWN clock — `self_fence_due`):
  `SELF-FENCED: renewal failed: membership lease is not custody …
  My deadline T_self is strictly earlier than the owner's TTL` + the
  purge line (`dropped 0 cached block key(s)` — a cold reader, honest).
* Row gates: `membership_self_fences` delta **exactly 1 on the victim,
  0 on all 31 others**; `membership_grace_refusals` 0 everywhere; rows
  VALID (R5 flat); clock-law inequality asserted from the published
  gauges (`T_self 42955 < T_owner 45000`). Victim restored and
  re-joined live at leg end. **GREEN.**

The "fences BEFORE the owner re-grants" half is the arithmetic the code
enforces (`T_self < T_owner`, owner acts only at ITS deadline) — under
SIGSTOP the victim's clock runs, so the fence fires by its own deadline
the moment it can run again, and the owner-side re-grant instant had
provably not been used to serve anything (reader; no writes exist).

## S6-b′ — hung-KERNEL self-fence via the VM pause verb (the 6b handoff)

Guest 0 (qemu/KVM, 6.19.14-sqz — an independent kernel AND an
independent clock domain, both REAL; large-skew injection stays on the
`membership_sim.rs` seam, unused here) joined the HOST fleet as a
cross-kernel read-only member: in-guest operator connects to the fleet
NQNs over slirp (10.0.2.2:54143), each resolved head VERIFIED against

fleet meta set, `membership_mode=member` dialing the owner's advertised
endpoint through slirp NAT. Owner census carried it (`member-reader`,
mount `/mnt/member`).

* `mw_fleet.sh pause 0` — vcpus + guest clock frozen, TCP left
  mid-conversation (the shape kill-9 cannot produce; SIGSTOP cannot
  freeze the clock).
* Owner (guest still frozen): `member 'd2cda92f…' (reader) EVICTED …
  lease epoch 35 is dead and its offsets are quarantined` +
  `custody dead-epoch:3 declared DEAD` — evicted + S7 dead epoch
  minted, uuid-keyed.
* Resume: the guest's monotonic domain never observed the gap
  (`self_fence_due` structurally false — the exact shape finding #1's
  fix exists for). In-guest asserts, all green:
  `membership_self_fences` 0→**1** (exactly), `SELF-FENCED` + purge

  epoch (35 → 36)** — fenced + purged FIRST, never a resume-as-live,
  never a resurrected epoch. Owner `membership_grace_refusals` flat.
  **GREEN** — and on the pre-fix binary this row is exactly the run

  `a_frozen_member_whose_lease_died_fences_and_purges_before_rejoining`

## Standing observations (not gated here)

* The `s6-journal` owner-cadence allowance (6 tx / 10 s beat, 2×
  headroom) is a measured constant of this tree; if the writer's own
  cadence economy changes, re-derive it rather than widening.
* `stale_ms` (reader staleness bound) published 2000 ms on every reader
  row — the S5 bound unchanged by the plane, as designed.
* The netem venue shapes only the daemon's USERSPACE wire (membership/
  cluster RPC): the NVMe fabric is kernel-plane and namespace-blind, so
  the victim keeps serving I/O while its liveness path is under duress
  — exactly the row's intent.
